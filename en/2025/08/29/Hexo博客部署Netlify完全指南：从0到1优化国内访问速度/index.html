Introduction

For many developers in China, deploying a Hexo blog using GitHub Pages often means dealing with slow access speeds — loading a single article can take several seconds or even longer, seriously hurting the reader experience. Netlify offers an elegant solution to this exact pain point. Known in the industry as the “ceiling of static site hosting,” it not only integrates perfectly with static blogs like Hexo but also redefines deployment efficiency and experience through a set of core features.

Netlify Core Advantages at a Glance

  • Global CDN Acceleration: Distributes static assets to nodes worldwide, significantly improving access latency in China
  • Fully Automated Deployment: Once linked to a GitHub repository, pushing code locally triggers automatic builds — say goodbye to manually running hexo deploy
  • Free Security Configuration: Automatically provisions SSL certificates, ensuring your blog is accessed securely over HTTPS

Netlify provides more than just hosting — it is a complete static site solution: from custom domain binding and JS/CSS asset compression to environment variable configuration and build log monitoring, it comprehensively covers the deployment needs of personal blogs[3][4]. Next, we will walk you step by step through the entire process, from linking your GitHub repository to optimizing access speed in China, so your Hexo blog can truly achieve “lightning-fast loading, automatic updates.”

Deployment Preparation

Environment Check

Before starting Hexo blog deployment, verifying the integrity of your local environment is a critical step to avoid subsequent deployment failures. This phase requires systematically checking from three dimensions: tool version confirmation, local preview testing, and code repository completeness, ensuring each aspect meets Netlify’s build requirements.

Basic Tool Version Verification

First, confirm that core development tools are properly installed and configured. As the runtime foundation of Hexo, Node.js is recommended to be managed through nvm (Node Version Manager) to avoid compatibility issues. Use nvm list available to view installable versions, nvm install <version> to install a specific version (such as Node.js 16.20.1 as shown in the example), and nvm use <version> to switch to it[5]. After installation, open the terminal and run the following commands to verify versions:

  • Node.js version: node -v (should return a specific version number, e.g. v16.20.1)
  • Hexo version: hexo -v (should return complete information like hexo-cli: 4.3.0)
  • Git version: git --version (ensure a valid version is returned, e.g. git version 2.40.0)[6][7]

If any command fails or the version number is missing, recheck the installation steps: Node.js should be downloaded from the official website as a stable version with default installation; Hexo requires global installation via npm install -g hexo-cli; Git needs to be downloaded from the official website with environment variables properly configured[6].

  • Port conflict: If you see Port 4000 has been used, switch to a different port with hexo s -p 5000 (e.g. 5000)
  • Browser proxy issues: Microsoft Edge may fail to connect due to automatic proxy settings; you’ll need to disable the proxy server in browser settings[6]

If the preview page loads article lists, theme styles, and navigation features correctly, your local environment is properly configured. If styles appear broken or pages are blank, check whether npm install fully installed all dependency packages, or whether theme files are missing.

GitHub Repository Completeness Check

Netlify deployment depends on the complete source code in your GitHub repository — missing critical files will directly cause build failures. Make sure your repository includes the following core content:

  • Theme files: The themes/ directory must be preserved intact (e.g. themes/next), including the theme configuration file _config.yml
  • Dependency configuration: package.json and package-lock.json (or yarn.lock) in the root directory must exist, recording the required dependency versions for the project
  • Hexo configuration: _config.yml (site configuration) and source/ (article source files) must be fully committed

It is recommended to use the git status command to check for untracked files, ensuring that core files beyond themes/ and node_modules/ are all under version control.

By completing the above three verification steps, you can effectively avoid deployment issues caused by incomplete environment configuration, laying a stable foundation for the subsequent automated build on Netlify.

Netlify Deployment Steps

Repository Connection and Build Configuration

After completing the local setup and code hosting for your Hexo blog, the next step is to connect your GitHub repository to the Netlify platform and configure the critical build parameters to ensure your blog can be deployed smoothly and generate accessible static pages.

1. Repository Connection: Linking GitHub with Netlify

Netlify supports pulling code directly from Git repositories for automatic deployment. It is recommended to use your GitHub account for quick login and repository authorization. The specific steps are as follows:

  1. Log in and create a new site: Visit the Netlify website, log in with your GitHub account for authorization, then click “New site from Git” or “Add a new project” in the dashboard to enter the repository selection page.
  2. Authorize and select a repository: Choose GitHub as the repository source. Netlify will request access to your GitHub repositories; after confirming authorization, select the repository containing your Hexo blog source code from the list (make sure the code has been uploaded to GitHub via git push).
  3. Branch selection: The default deployment branch is the main branch (such as master or main). If your blog source code is stored in another branch, manually specify it under “Branch to deploy”.

Note: If your repository contains a subdirectory structure (e.g. the configuration file package.json is not in the root directory), you need to set the “Base directory” in Netlify to specify the actual path, otherwise the build system may fail because it cannot find the dependency configuration.

2. Build Configuration: Key Parameter Settings and Principles

After entering the build settings page, you need to focus on configuring the build command and publish directory — these two parameters directly determine whether deployment succeeds.

1. Build Command: Why do you need npm install + hexo generate?

The Hexo blog build process is divided into two steps:

  • Dependency installation: Download the dependency packages declared in package.json (such as Hexo core modules, theme plugins, etc.) via npm install. If this step is skipped, the Netlify server will be unable to execute subsequent commands due to missing required dependencies (such as hexo-cli), with a common error being “command failed with exit code 1”.
  • Static file generation: Compile Markdown articles, theme configurations, etc. into HTML/CSS/JS static files via hexo generate (shorthand hexo g), output by default to the public directory.

When configuring, you can directly fill in the combined command npm install && hexo generate, or define a build script in package.json (e.g. "build": "hexo generate") and then fill in npm run build in Netlify (make sure the script includes dependency installation logic, or Netlify will automatically run npm install).

2. Publish Directory: Specifying the Static File Location

Hexo generates static files in the public directory by default, so you need to set Netlify’s “Publish directory” to public. If you mistakenly set it to another directory (such as dist or build), Netlify will fail to deploy because it cannot find deployable files.

3. Configuration Entry Point and Saving Deployment

In the Netlify interface, the build settings entry is located in the “Build settings” step after selecting the repository, specifically as follows:

  • Build command: Fill in npm install && hexo generate or npm run build (choose based on your project configuration).
  • Publish directory: Always fill in public (the default output directory for Hexo).

After confirming the parameters are correct, click “Deploy site”. Netlify will automatically clone the repository code, install dependencies, execute the build command, and deploy the contents of the public directory to the global CDN. Once deployment is complete, you can access your blog through the random domain generated by Netlify (format: [random-string].netlify.app) to verify that pages load correctly.

By following the above steps, you can complete the repository connection and build configuration, ensuring your Hexo blog deploys stably on Netlify. The next section will cover how to optimize access speed in China, further enhancing your blog’s usability.

Domain Configuration and HTTPS Activation

Having a custom domain not only makes your blog look more professional but also enhances memorability for users. After completing this step, Netlify will automatically configure HTTPS encryption for your blog, making access more secure. Let’s walk through domain binding and security hardening step by step.

1. Adding a Custom Domain on Netlify

First, log in to your Netlify account, navigate to your Hexo blog site dashboard, go to “Domain management” → “Production domains” and click “Add domain”. Enter your own domain name (e.g. example.com) and confirm. Once added, this domain will automatically become the primary domain for your blog, replacing the default xxx.netlify.app subdomain[9].

Note: When adding a domain, make sure there are no duplicate bindings. If a conflict is reported, you can remove the old DNS zone records in Netlify’s domain settings[10].

2. DNS Resolution Configuration (Using Alibaba Cloud as an Example)

This step requires modifying DNS records in your domain provider’s backend (such as Alibaba Cloud, Tencent Cloud, etc.) to point your domain to Netlify’s servers. Choose different configurations based on the domain type (apex domain / subdomain):

Domain Type Recommended Record Type Host Record Value Description
www subdomain CNAME www your-site.netlify.app (e.g. blog.netlify.app) Points www.example.com to the subdomain assigned by Netlify
Apex domain (example.com) CNAME (if supported) @ apex-loadbalancer.netlify.com If your DNS provider supports CNAME flattening (ALIAS records), use this first
Apex domain (example.com) A record (if CNAME not supported) @ 75.2.60.5 If CNAME is not supported, add an A record pointing to Netlify’s load balancer IP, avoiding risks of hardcoded IP changes

Configuration Tips:

  • Alibaba Cloud users can go to “Domain Resolution” → “Add Record” and fill in the parameters according to the table above;
  • If there are old A records (e.g. pointing to GitHub or other servers), delete them first before adding new records;
  • Subdomains and apex domains can be configured simultaneously, enabling dual access via both example.com and www.example.com[10][11].

3. Verifying DNS Propagation Status

DNS record updates do not take effect immediately — you need to wait for global DNS servers to synchronize (usually 10-30 minutes, no longer than 48 hours at most). You can verify whether the configuration has taken effect using terminal commands:

  • Verify apex domain: Run host example.com; the result should include 75.2.60.5 (A record) or apex-loadbalancer.netlify.com (CNAME);
  • Verify www subdomain: Run host www.example.com; the result should include your Netlify subdomain (e.g. blog.netlify.app)[10].

Tip: If you want to quickly check DNS propagation progress, you can use online tools (such as DNS Checker) to enter your domain and view the resolution status across various global locations.

4. Automatic HTTPS Activation and Its Security Value

When DNS correctly points to Netlify, the system will automatically perform the following:

  1. Certificate generation: Netlify automatically issues a free SSL certificate via Let’s Encrypt — no manual upload required;
  2. HTTPS activation: HTTPS is enabled by default with forced redirection (HTTP requests are automatically redirected to HTTPS);
  3. Certificate renewal: Certificates are valid for 90 days; Netlify will automatically renew them in advance without any manual intervention[3][12].

Why must HTTPS be enabled?

  • Security perspective: Encrypts user data transmission, preventing content tampering;
  • User experience perspective: Modern browsers (such as Chrome, Firefox) label HTTP sites as “Not Secure,” affecting visitors’ willingness to browse;
  • SEO perspective: Search engines like Google prioritize HTTPS sites, boosting ranking weight[13].

If HTTPS isn’t enabled as expected, first check whether the DNS records are correct (incorrect DNS pointing will prevent certificate generation), then click “Renew certificate” in Netlify’s “HTTPS” settings to manually trigger certificate renewal[14].

After completing the above steps, your Hexo blog will have a custom domain and HTTPS encryption, with significantly improved access speed and security.

“build command failed” Error Solutions

Dependency Installation and Version Compatibility Issues

During the Netlify deployment of a Hexo blog, build failures are often related to incomplete dependency installation or version compatibility issues. The root causes of these two types of problems are closely tied to the characteristics of Netlify’s build environment and require targeted solutions to ensure a smooth deployment process.

Dependency Installation: From “command not found” to Complete Deployment

Netlify’s build environment runs in production mode (NODE_ENV=production) by default, meaning only the dependencies declared in the dependencies field of package.json are installed, while tools in devDependencies (such as hexo-cli) are not automatically installed. This directly leads to “command not found” errors (e.g. “hexo: command not found”) or missing module errors in the build logs.

Conclusion

By deploying your Hexo blog on Netlify, you can say goodbye to tedious manual deployment workflows and achieve full-process automation from local modifications and GitHub commits to automatic deployment, significantly boosting your blog publishing efficiency[1][8]. At the same time, the free HTTPS certificates and flexible DNS configuration provided by Netlify not only enhance your blog’s security but also effectively improve the site’s global availability, making the access experience smoother for readers in China.

Of course, there are certain key details to pay attention to during the deployment process. Core Considerations: Ensure clear project dependency management to avoid build failures caused by version conflicts; carefully verify DNS resolution records during DNS configuration to ensure correct resolution targets; validate build commands locally beforehand to avoid deployment interruptions due to command errors. Mastering these details is a crucial guarantee for a smooth blog launch.

If you’re still troubled by the complexity of blog deployment, feel free to follow the steps in this article and give it a try. After deployment, remember to regularly monitor Netlify’s build logs and domain resolution status, promptly identify and resolve potential issues, so your Hexo blog can run stably over the long term and provide readers with a more reliable access experience. The value of technology lies in simplifying processes and improving efficiency — the combination of Netlify and Hexo is the perfect embodiment of this philosophy.
