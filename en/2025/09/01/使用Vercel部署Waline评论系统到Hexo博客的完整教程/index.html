Introduction

Many friends have recently reached out through private messages asking about comment systems. For static blog users, setting up a comment system often falls into the dilemma of “unable to balance convenience and security”: backend-free solutions are lightweight but pose data leakage risks, while traditional backend systems have steep learning curves. Waline, a next-generation comment system built on Valine, perfectly balances security and ease of use through its innovative “backend architecture + lightweight deployment” model, making it an ideal choice for Hexo and other static blogs. This website also uses this comment system, so I wrote this article after consulting extensive reference materials.

Waline: Making Comment Systems Both Secure and Powerful

Building on Valine’s simplicity, Waline focuses on strengthening its security kernel and functional depth. It employs multiple layers of encryption to protect user data, fundamentally solving Valine’s security risk of exposing LeanCloud keys on the frontend. At the same time, through anonymous login content verification, anti-spam mechanisms, and sensitive information filtering, it effectively guards against spam comment attacks. On the functionality side, it offers an interactive experience comparable to professional communities: supporting diverse comment formats including text, emojis, and images; compatible with Markdown syntax, mathematical formulas, and even HTML embedding; and built-in tools for comment moderation, reply notifications, and report handling, paired with multiple theme styles and customization options to meet the diverse needs of everything from personal blogs to technical sites.

Waline Core Advantages at a Glance
✅ Security Upgrade: Rebuilt on Valine’s architecture with multiple encryption layers + anti-spam mechanisms
✅ Full-Featured: Supports Markdown/emoji/image comments, built-in comment management and multi-platform login
✅ Cross-Platform: Seamlessly integrates with Hexo, VuePress, and other static blog systems

Why Deploy on Vercel?

As a comment system with a backend, Waline requires an independent server. Vercel, with its “zero-ops” characteristics, is the optimal deployment solution. This popular frontend deployment platform provides a one-stop solution: deploy simply by connecting a GitHub repository, with no command-line operations needed throughout the entire process; global CDN nodes ensure millisecond comment loading; and the free tier includes automatic SSL certificates, Serverless function support, and unlimited bandwidth, fully covering personal blog use cases. Compared to other deployment methods, Vercel compresses what would normally take hours of server configuration into a few minutes of “click authorize - auto deploy,” allowing even tech novices to easily own a professional-grade comment system.

This article focuses on the complete workflow of “Vercel Deployment of Waline + Hexo Integration”, covering everything from server deployment and database configuration to frontend integration, providing reusable operation guides and practical tips throughout. Whether you’re a blog newcomer touching comment systems for the first time or an advanced user looking to upgrade your existing commenting functionality, this tutorial will help you set up a secure, efficient, and visually appealing interactive system within 15 minutes, truly bringing your static blog to life.

Prerequisites

Before starting the Waline comment system deployment, please ensure the following preparations are complete. This will help you smoothly advance through the subsequent deployment process. We’ll organize preparations across three dimensions – account registration, tool environment configuration, and blog environment checks – with key considerations highlighted.

1. Core Account Preparation

Deploying Waline requires two key platforms: Vercel (server deployment) and LeanCloud (data storage). It is recommended to complete registration and basic configuration in advance.

1.1 Vercel Account

  • Purpose: Serves as the hosting platform for the Waline server, providing free deployment and global CDN acceleration.
  • Registration Method: Visit the official website. It is recommended to use GitHub account quick login (no additional registration needed, directly linked to code repositories).
  • Notes: No additional configuration is needed after login. Simply connect the Waline code repository during the subsequent deployment.

1.2 LeanCloud Account

  • Purpose: Provides database services to store core data such as comments and user information.
  • Registration & Configuration:
    1. Visit leancloud, register an account (domestic users in China are advised to choose the East China/North China node; international users may choose the international version).
    2. Create an app: After entering the console, click “Create App” and select “Development Version” (the free tier is sufficient for personal blog needs).
    3. Obtain keys: In the app’s settings under “App Keys,” record the App ID, App Key, and Master Key (these three parameters will be needed for subsequent deployment).
  • Special Requirement: Apps on domestic nodes require an additional bound ICP-filed domain (path: Settings → Security Center → Web Security Domain), otherwise comment data will not read or write properly.

2. Local Tool Environment Configuration

Ensure the following tools are installed locally for executing deployment commands and managing the Hexo blog:

2.1 Basic Development Environment

  • Node.js and npm/yarn

    • Purpose: Run the Hexo blog and install Waline-related dependencies.
    • Check Method: Execute node -v and npm -v (or yarn -v) in the terminal. Displayed version numbers indicate installation (Node.js ≥ 14.0.0, npm ≥ 6.0.0 recommended).

  • Git

    • Purpose: Version control tool for pulling Waline source code and managing Hexo blog code.
    • Check Method: Execute git --version in the terminal. A displayed version number indicates normal status.

2.2 Vercel CLI (Optional but Recommended)

  • Purpose: Execute Vercel deployment commands locally without logging into the web console each time.
  • Installation Method: Execute npm i -g vercel in the terminal (global installation). Verify the version with vercel -v.

3. Hexo Blog Environment Check

Before deploying Waline, ensure the Hexo blog is running normally and the theme supports comment system configuration:

  • Basic Environment: A blog project has been created via hexo init. Running hexo s enables preview at http://localhost:4000.
  • Theme Compatibility: It is recommended to use themes that support Waline, such as Next (≥8.18.2), Yun, Sea, etc. Confirm that the theme configuration file (e.g., _config.next.yml) contains comment system-related settings.
  • Configuration File Standards: It is recommended to use theme configuration file overrides (rather than directly modifying the theme’s default configuration). For example, create _config.next.yml in the blog root directory to manage theme settings separately.

4. Optional Preparation: Custom Domain (Configure as Needed)

If you need to access the Waline service through a personalized domain (e.g., comment.yourblog.com), prepare the following in advance:

  • An ICP-filed domain (for domestic users in China), and add a CNAME record pointing to Vercel on your domain resolution platform.
  • Purpose: Bind the Vercel-deployed server or the LeanCloud domestic app (to solve domain restriction issues).

Key Reminder: After all account registrations are complete, properly save the relevant keys (such as LeanCloud’s Master Key), as they will be used frequently in subsequent deployment steps. If using the domestic version of LeanCloud, be sure to complete domain filing and binding in advance to avoid comment functionality failure due to cross-origin issues.

Once the above preparations are complete, you can proceed to Waline server deployment and Hexo integration.

Detailed Steps

LeanCloud Configuration

Data storage for the Waline comment system depends on the LeanCloud platform. We need to first complete account registration and app configuration. Here are the detailed steps:

1. Register and Log In

Visit the LeanCloud console (International version: console.leancloud.app, Domestic version: console.leancloud.cn), and register using email or third-party accounts.
Note: The domestic version requires domain ICP filing. To avoid additional procedures, using the international version is recommended.

2. Create a Development App

After logging into the console, click “Create App” and follow these steps:

  • Enter an app name (custom, such as “MyBlogComments”);
  • Select “Development Version” (free tier sufficient for personal blog needs);
  • Click “Create” to complete app initialization.

3. Obtain App Credentials

After the app is created, navigate to “Settings” → “App Keys” in the left sidebar and record the following key information (needed for subsequent deployment):

  • APP ID: Unique app identifier;
  • APP Key: App access key;
  • Master Key: Elevated operation key (used for data management).

Important Note: The Master Key holds the highest privileges; do not disclose it to third parties. It is recommended to take screenshots or use a password manager to save these three keys.

4. Configure Security Domain (Optional)

To prevent unauthorized websites from calling the API, add your blog domain (e.g., https://yourblog.com) in “Settings” → “Security Center” → “Web Security Domain”. During local debugging, localhost is automatically allowed without additional configuration.

5. Special Configuration for Domestic Version (Domestic Users Only)

If using the LeanCloud domestic version, two additional operations are required:

  1. Bind an ICP-filed domain: Bind an ICP-filed custom domain in the LeanCloud console;
  2. Record the server address: Use the bound domain (e.g., https://comments.yourblog.com) as the LEAN_SERVER environment variable value, which must be configured during subsequent deployment.

Must-Read for Domestic Users: Failure to configure LEAN_SERVER will cause service connection failure. International users may skip this step.

After completing the above configuration, you now have the core credentials for your LeanCloud app, ready for environment variable settings during Vercel deployment.

Deploying Waline Server on Vercel

Deploying the Waline server via Vercel templates is the quickest method, requiring no local environment configuration – everything can be done through web operations. Here are the detailed steps:

1. Deploy Waline Service

First, visit the Waline official template page (findable through Waline documentation or GitHub repository), and click the “Deploy to Vercel” button on the page. The system will automatically redirect to the Vercel deployment interface. After logging into Vercel with your GitHub account, enter a project name (e.g., waline-server) and click “Create” to create the project. Vercel will automatically initialize the repository based on the template and begin deployment. Just wait for the deployment progress to complete. The first deployment will generate a temporary preview address, but it won’t be usable yet – because you still need to configure critical environment variables.

2. Configure Environment Variables

Environment variables are the core configuration for Waline to connect to the database, and they must be filled in accurately to ensure normal service operation. After deployment, enter the Vercel project console and click “Settings” > “Environment Variables” to add the following variables:

Environment Variable Description Example Value Format Applicable Scenarios
LEAN_ID LeanCloud App ID iGxxxxxxxxxxxxxxxxxxxxxxA Required for all users
LEAN_KEY LeanCloud App Key 7fxxxxxxxxxxxxxxxxxxxxxxB Required for all users
LEAN_MASTER_KEY LeanCloud Master Key 9cxxxxxxxxxxxxxxxxxxxxxxC Required for all users
LEAN_SERVER LeanCloud Server Address https://your-leancloud-domain.com Additional for domestic users

Notes:

  • Environment variable values must be obtained from the “App Settings > App Keys” section of the LeanCloud console. Ensure no spaces or extraneous characters are included when copying.
  • Domestic users using the LeanCloud domestic version must add LEAN_SERVER and fill in the ICP-filed custom domain (which must be bound in LeanCloud in advance), otherwise cross-origin issues will cause comment functionality to fail.

After adding, click “Save” to save the variables. Note that variables will not take effect immediately – you must perform a “Redeploy” operation.

3. Redeploy the Project

After modifying environment variables, Vercel will not automatically update the existing deployment. You need to manually trigger a redeployment to make the configuration effective. Go to the “Deployments” tab in the project console, find the latest deployment record (usually at the top of the list), click the “Redeploy” button on the right, and confirm. Wait for deployment to complete (about 1-3 minutes).

4. Obtain the Server Address

After a successful redeployment, the STATUS of the deployment record will display as “Ready”. Click the “Visit” button on the right to access the server. The URL in the browser’s address bar at this point (e.g., https://waline-server.vercel.app) is your Waline server address. Be sure to copy and save it – you will need to fill in this address (corresponding to the serverurl parameter) in the subsequent Hexo blog configuration.

If you need a custom domain (optional), go to “Settings” > “Domains”, enter your domain (e.g., waline.yourblog.com), and add a CNAME record at your domain registrar (pointing to cname.vercel-dns.com). Once configured, the custom domain will serve as an alternative to the server address. It is recommended to keep the default Vercel domain as a backup.

Key Tip: The server address is the bridge connecting the blog to the comment system. If you later change the domain or redeploy, you must synchronously update the serverurl in the blog configuration, otherwise the comment functionality will stop working.

Security & Anti-Spam

An open comment section is an important window for blog-reader interaction, but spam comments and malicious submissions can impact the reading experience. Waline provides multiple layers of security protection mechanisms. By properly configuring environment variables, you can effectively safeguard your comment area. Here are key security strategies and configuration guides:

1. Anti-Spam Service Configuration

Waline has various built-in anti-spam mechanisms. Enable professional anti-spam services and human verification through environment variables to block malicious comments at the source.

1.1 Akismet Anti-Spam Service
As an industry-renowned anti-spam comment service, Akismet can automatically identify spam comments. Waline integrates this service by default, usable without additional deployment.

  • Environment Variable: AKISMET_KEY
  • Purpose: Fill in your Akismet API Key to enable the feature. If not needed, explicitly set to false (leaving it empty may cause the default key to remain active).
  • Default Value: 70542d86693e (Test key; replace with a personal key for production).

1.2 Human Verification Mechanisms
To counter malicious comments submitted by automated tools, enable third-party human verification (requires synchronized server and client configuration):

  • reCAPTCHA V3: Requires both RECAPTCHA_V3_KEY (client verification key) and RECAPTCHA_V3_SECRET (server secret).
  • Cloudflare Turnstile: A lightweight verification solution. Configure TURNSTILE_KEY to enable it, suitable for scenarios with higher UX requirements.

2. Comment Moderation and Content Control

Through moderation mechanisms and rate limiting, further filter suspicious comments and prevent comment area abuse.

2.1 Manual Comment Moderation
When moderation is enabled, all new comments require administrator approval in the Waline backend before being displayed, preventing inappropriate content from being directly published.

  • Environment Variable: COMMENT_AUDIT
  • Configuration Value: Set to true to enable moderation, false for direct publication.

Note: After enabling moderation, regularly log into the Waline management console (usually accessible via YOUR_DEPLOY_URL/ui) to process pending comments, avoiding accumulation that affects interaction timeliness.

2.2 IP-Based Comment Rate Limiting
Limit the comment posting speed from the same IP address to prevent mass spamming in a short period.

  • Environment Variable: IPQPS
  • Purpose: Unit is seconds. Default value is 60 (meaning the same IP can only submit 1 comment per minute). Set to 0 for no limit.

3. Security Domains and Access Control

Restrict the calling sources of the comment system to prevent unauthorized websites from abusing your comment service.

Security Domain Configuration
Specify domains allowed to submit comments. Only requests from these domains will be processed, effectively preventing Cross-Site Request Forgery (CSRF).

  • Environment Variable: SECURE_DOMAINS
  • Configuration Value: Fill in your blog domain (e.g., example.com). Separate multiple domains with commas (e.g., blog.example.com,www.example.com).

Email Notification Settings

The email notification feature is an important element for enhancing blog interaction experience. It allows you to receive new comment alerts in a timely manner while ensuring commenters are immediately notified when they receive replies. When a new comment is submitted, the system sends a notification to the blogger’s email; when a comment is replied to, the commenter is notified through the email they provided. The site name and URL in notifications will automatically read the information you have filled in the “Site Management / System Settings / Site Configuration.”

Basic Configuration Steps

First, enable the email notification feature in the system, then fill in the SMTP service-related information. Here is a detailed configuration guide:

SMTP Parameters for Major Email Providers

Different email providers have different SMTP settings. Here we explain using QQ Mail and 163 Mail as examples:

QQ Mail Configuration

  • SMTP Address (host): For personal accounts, use smtp.qq.com; for business accounts, use smtp.exmail.qq.com
  • SMTP Port: 465 (SSL encryption) or 587 (TLS encryption)
  • SMTP Username: Your full QQ email address (e.g., 12345678@qq.com)
  • SMTP Password: An authorization code generated in QQ Mail settings (NOT your login password)
  • Sender Address: Must match the SMTP username, otherwise a 501 Mail from address must be same as authorization user error may occur

163 Mail Configuration (general reference)

  • SMTP Address: smtp.163.com
  • SMTP Port: 465 or 994 (SSL)
  • SMTP Password: 163 Mail requires enabling the “SMTP Service” and setting an independent authorization code

Notes: SMTP passwords for all email providers are independent authorization codes, not login passwords. The method to obtain them is usually found in the “Account” or “Security” section of your email settings. For example, in QQ Mail, go to “Settings → Account → POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV Services,” enable the “SMTP Service,” and click “Generate Authorization Code.”

Environment Variable Configuration (Docker Deployment Scenario)

If your Waline is deployed via Docker Compose, add the following environment variables to your docker-compose.yml:

Core Environment Variable Descriptions

When configuring email notifications, distinguish between required and optional variables to ensure key parameters are set correctly:

Required Variables

  • SMTP_SERVICE / SMTP_HOST / SMTP_PORT: Email server information (choose either; SMTP_SERVICE supports auto-filling server info for major providers)
  • SMTP_USER: Sender email address
  • SMTP_PASS: Email authorization code
  • SITE_NAME / SITE_URL: Blog name and URL (used for site identification in notification content)
  • AUTHOR_EMAIL: Blogger email (receives new comment notifications; the blogger’s own comments will not trigger notifications)

Optional Variables (to customize notification experience)

  • SENDER_NAME: Custom sender name (e.g., “Blog Assistant”)
  • MAIL_SUBJECT / MAIL_TEMPLATE: Subject and content template for comment reply emails
  • MAIL_SUBJECT_ADMIN / MAIL_TEMPLATE_ADMIN: Subject and content template for new comment notifications to the blogger

Common Troubleshooting

If email notifications don’t work after configuration, check the following steps:

  1. Is the authorization code correct?: Confirm that the SMTP password is the independent authorization code generated by your email provider, not your login password.
  2. Port and encryption method match: Port 465 corresponds to SMTP_SECURE: 'true'; port 587 typically corresponds to SMTP_SECURE: 'false'.
  3. Sender address consistency: Ensure SMTP_USER is exactly the same as the actual sender address.
  4. Service restart: After modifying configuration, restart the Waline service to apply changes.

With the above configuration, your blog’s comment system will have comprehensive email notification capabilities, improving both the blogger’s management efficiency and giving visitors a more timely interactive feedback experience.

Common Issues & Solutions

Deployment Issues

When deploying the Waline comment system on Vercel, you may encounter various types of failures. Below are common issues and solutions summarized from real deployment scenarios to help you quickly identify and resolve problems.

Environment Variable Configuration Errors

This is the most common cause of deployment failures, primarily manifesting as the service being unable to connect to the database or experiencing functional abnormalities after startup. Carefully check whether the environment variables in Vercel deployment settings are complete and correct:

  • Core Variable Check: Ensure LEAN_ID (App ID), LEAN_KEY (App Key), and LEAN_MASTER_KEY (Master Key) are all accurately copied from the LeanCloud app console, avoiding extra spaces or characters.
  • Redeploy to Apply: After modifying environment variables, you must click Redeploy in the Vercel project console. Simply saving variables will not trigger a service update.

Note: Environment variable names are case-sensitive. For example, LEAN_ID must not be mistakenly written as lean_id or Lean_Id, or service initialization will fail.

LeanCloud App Configuration Issues

If you encounter a Not initialized error or a 404 page after deployment, it is usually related to LeanCloud app configuration:

  • App Creation Verification: Log into the LeanCloud console and confirm that the target app has been successfully created and that its region (e.g., North China, East China) matches the Waline server.
  • Permission Settings Check: Go to the app’s “Settings > Security Center” and ensure your blog domain (e.g., https://yourblog.com) has been added to the “Web Security Domain,” or temporarily disable “Referer Verification” for testing.

Project Association and Deployment Method Issues

Some users may encounter deployment failures due to the project not being correctly associated with a Git repository:

  • Git Repository Association: When importing a project through Vercel, ensure you select the correct Git repository and branch (usually main or master), and enable the auto-deploy option.
  • CLI Deployment Alternative: If web-based import fails, use Vercel CLI in the local project root directory and execute vercel --prod to force deployment. This method automatically associates the local repository and uploads the code.

Cache and Dependency Issues

Deployment processes may fail due to cache or dependency download anomalies:

  • Clear Cache and Redeploy: On the Vercel deployments page, click “More > Clear Cache & Redeploy” beside the corresponding deployment record to forcefully clear old caches and re-pull dependencies.
  • Dependency Source Optimization: If the deployment log shows dependency download timeouts, add a .npmrc file in the project root directory and configure a domestic mirror source (e.g., registry=https://registry.npmmirror.com).

How to View Vercel Deployment Logs

When the above steps cannot resolve the issue, use deployment logs to identify specific errors:

  1. Log into the Vercel console and enter the corresponding project.
  2. Click the “Deployments” tab at the top and select the most recent failed deployment record.
  3. In the deployment details page, view “Build Logs” or “Runtime Logs,” focusing on red-highlighted error messages (e.g., Error: LeanCloud initialization failed), and troubleshoot further based on the prompts.

Through the above steps, most deployment issues can be identified and resolved. If you encounter complex errors, it is recommended to submit the complete logs and error screenshots to the Waline official repository or relevant tech communities for more targeted assistance.

Comments Not Displaying

A blank comment area is the most common issue when deploying Waline. Below is a step-by-step troubleshooting plan to help you quickly pinpoint the root cause.

1. Basic Configuration Check

1.1 Is the server address correct?
First, confirm whether the serverURL field in the Hexo theme configuration file (e.g., _config.next.yml or _config.butterfly.yml) accurately points to the Vercel-deployed server address. The format should be https://xxxx.vercel.app (replace with your actual domain). An incorrect address will prevent the comment system from connecting to the backend, directly causing a blank page.
Also check whether the server environment variables are complete (such as MONGODB_URI, JWT_SECRET, etc.). Missing critical variables will prevent the server from starting normally.

1.2 Regenerate blog content
If the configuration was modified without regeneration, new settings will not take effect. Execute the following command in the terminal to clear the cache and rebuild:
hexo clean && hexo g
After generation, redeploy (e.g., hexo d), and force-refresh the browser page (shortcut Ctrl+Shift+R).

1.3 Verify server operational status
Directly visit your Waline server address in the browser (e.g., https://xxxx.vercel.app). If the page displays “Waline server is running” or the comment management interface, the server is operational. If it shows a 404 or error page, check the environment variable configurations or build errors in the Vercel deployment logs.

Domestic Access Issues (China)

Many users encounter slow loading or complete inability to load the Waline comment system when accessing from within China. This is primarily because Vercel’s default vercel.app domain suffers from DNS pollution domestically, preventing normal use of the comment system. Fortunately, Vercel’s server IPs are not blocked. We can completely solve this problem by binding a custom domain, allowing domestic users to access the comment system smoothly.

Solution Steps: Bind a Custom Domain

1. Add a Custom Domain in Vercel

First, configure your own domain in the Vercel project. Go to the Waline project’s Settings → Domains page, enter the domain you intend to use for the comment system (e.g., comment.yourblog.com), click add, and wait for Vercel to verify domain ownership.

2. Set a CNAME Record at Your Domain Registrar

Log into the DNS management platform of your domain registrar (such as Alibaba Cloud, Tencent Cloud, etc.) and add the following DNS record to point your custom domain to Vercel’s servers:

Record Type Host Record Record Value Description
CNAME comment cname.vercel-dns.com Assuming comment is used as the subdomain
CNAME @ cname.vercel-dns.com If using the root domain directly (e.g., yourblog.com)
CNAME www cname.vercel-dns.com If using the www subdomain

The host record can be chosen based on your needs. It is recommended to use an independent subdomain (e.g., comment) to avoid conflicts with the main blog domain.

3. Update the Server Address in Hexo Configuration

After completing domain resolution, change the serverURL field in Hexo’s Waline configuration to the newly bound custom domain (e.g., https://comment.yourblog.com), ensuring the blog can correctly connect to the comment system.

Notes

  • Domain resolution may take from 10 minutes to 24 hours to take effect. Check the resolution status using the ping command or DNS detection tools.
  • If using the LeanCloud domestic version as the database, also set LEAN_SERVER to the domestic service address in Vercel environment variables to ensure normal data interaction.

Through the above steps, domestic users can smoothly access the Waline comment system through your custom domain, avoiding access obstacles caused by Vercel’s default domain issues. This solution is not only stable and reliable but also enhances the professionalism and user experience of your blog.

2. Core Parameter Details

In addition to comments, the following parameters also directly affect the normal operation of the comment system. Configure them as needed:

Parameter Description Notes
