簡介

最近有很多朋友私信問到評論系統的問題，對於靜態博客用戶而言，評論系統的搭建常常陷入"便捷與安全不可兼得"的困境：無後端方案雖輕量卻存在數據泄露風險，傳統帶後端系統又門檻過高。而Waline作為基於Valine開發的新一代評論系統，通過"帶後端架構+輕量化部署"的創新模式，完美平衡了安全性與易用性，成為Hexo等靜態博客的理想選擇，本網站也采用此評論系統，所以參考了很多文獻資料寫了這篇文章。

Waline：讓評論系統既安全又強大

Waline在繼承Valine簡潔基因的基礎上，重點強化了安全內核與功能深度。其采用多重加密技術保護用戶數據，從源頭解決了Valine因前端暴露LeanCloud密鑰導致的安全隱患，同時通過匿名登錄內容校驗、防灌水機制和敏感信息過濾，有效抵禦垃圾評論攻擊。功能層面，它提供了媲美專業社區的交互體驗：支持文字、表情、圖片等多元評論形式，兼容Markdown語法、數據公式甚至HTML嵌入；內置評論審核、回復通知、舉報處理等管理工具，搭配多套主題樣式和自定義設置，滿足從個人博客到技術站點的多樣化需求

Waline核心優勢速覽
✅ 安全升級：基於Valine架構重構，多重加密防護+防垃圾評論機制
✅ 功能全面：支持Markdown/表情/圖片評論，內置評論管理與多平台登錄
✅ 跨平台兼容：無縫對接Hexo、VuePress等靜態博客系統

為什麽選擇Vercel部署？

作為帶後端的評論系統，Waline需要獨立的服務端支撐，而Vercel憑借其"零運維"特性成為最佳部署方案。這個流行的前端部署平台提供了一站式解決方案：通過GitHub倉庫連接即可完成部署，全程無需命令行操作；全球CDN節點確保評論加載毫秒級響應；免費套餐包含自動SSL證書、Serverless函數支持和無限流量，完全覆蓋個人博客的使用場景。相比其他部署方式，Vercel將原本需要數小時的服務器配置流程壓縮到"點擊授權-自動部署"的幾分鐘內，讓技術新手也能輕松擁有專業級評論系統。

本文將聚焦**“Vercel部署Waline+Hexo集成”**的完整流程，從服務端部署、數據庫配置到前端集成，全程提供可復用的操作指南和避坑技巧。無論你是初次接觸評論系統的博客新手，還是希望升級現有評論功能的進階用戶，都能通過本教程在15分鐘內搭建起安全、高效且美觀的互動系統，讓靜態博客真正"活"起來。

準備工作

在開始部署 Waline 評論系統前，請確保完成以下準備工作，這將幫助你順利推進後續部署流程。我們將從賬號注冊、工具環境配置到博客環境檢查三個維度進行梳理，並標注關鍵注意事項。

一、核心賬號準備

部署 Waline 需依賴兩個關鍵平台：Vercel（服務端部署）和 LeanCloud（數據存儲），建議提前完成注冊與基礎配置。

1. Vercel 賬號

  • 作用：作為 Waline 服務端的托管平台，提供免費部署與全球 CDN 加速能力。
  • 注冊方法：訪問[官網]，推薦使用 GitHub 賬號快捷登錄（無需額外注冊，直接關聯代碼倉庫）。
  • 注意事項：登錄後無需額外配置，後續部署時直接關聯 Waline 代碼倉庫即可。

2. LeanCloud 賬號

  • 作用：提供數據庫服務，存儲評論內容、用戶信息等核心數據。
  • 注冊與配置：
    1. 訪問[leancloud]，注冊賬號（國內用戶建議選擇華東/華北節點，海外用戶可選國際版）。
    2. 創建應用：進入控制台後點擊"創建應用"，選擇"開發版"（免費額度滿足個人博客需求）。
    3. 獲取密鑰：在應用設置的"應用 Keys"中，記錄 App ID、App Key 和 Master Key（後續部署需填入這三個參數）。
  • 特殊要求：國內節點應用需額外綁定已備案域名（路徑：設置 → 安全中心 → Web 安全域名），否則評論數據無法正常讀寫。

二、本地工具環境配置

確保本地已安裝以下工具，用於執行部署命令和管理 Hexo 博客：

1. 基礎開發環境

  • Node.js 與 npm/yarn

    • 作用：運行 Hexo 博客和安裝 Waline 相關依賴。
    • 檢查方法：終端執行 node -v 和 npm -v（或 yarn -v），輸出版本號即表示已安裝（推薦 Node.js ≥ 14.0.0，npm ≥ 6.0.0）。

  • Git

    • 作用：版本控制工具，用於拉取 Waline 源碼和管理 Hexo 博客代碼。
    • 檢查方法：終端執行 git --version，輸出版本號即正常。

2. Vercel CLI（可選但推薦）

  • 作用：本地執行 Vercel 部署命令，無需每次登錄網頁控制台。
  • 安裝方法：終端執行 npm i -g vercel（全局安裝），安裝後用 vercel -v 驗證版本。

三、Hexo 博客環境檢查

部署 Waline 前，需確保 Hexo 博客已正常運行，且主題支持評論系統配置：

  • 基礎環境：已通過 hexo init 創建博客項目，執行 hexo s 可在本地 http://localhost:4000 預覽。
  • 主題兼容性：推薦使用支持 Waline 的主題，如 Next（≥8.18.2）、Yun、Sea 等，需確認主題配置文件（如 _config.next.yml）中存在評論系統相關設置項。
  • 配置文件規範：建議通過主題配置文件覆蓋（而非直接修改主題默認配置），例如在博客根目錄創建 _config.next.yml 單獨管理主題設置。

四、可選準備：自定義域名（按需配置）

若需使用個性化域名訪問 Waline 服務（如 comment.yourblog.com），需提前準備：

  • 已備案域名（國內用戶），並在域名解析平台添加指向 Vercel 的 CNAME 記錄。
  • 用途：綁定 Vercel 部署的服務端或 LeanCloud 國內版應用（解決域名限制問題）。

關鍵提示：所有賬號注冊完成後，請妥善保存相關密鑰（如 LeanCloud 的 Master Key），後續部署步驟將頻繁使用。若使用國內版 LeanCloud，務必提前完成域名備案和綁定，避免因跨域問題導致評論功能失效。

完成以上準備後，即可進入 Waline 服務端部署和 Hexo 集成環節。

詳細步驟

LeanCloud配置

Waline 評論系統的數據存儲依賴於 LeanCloud 平台，我們需要先完成賬號注冊與應用配置。以下是詳細步驟：

1. 注冊與登錄賬號

訪問 LeanCloud 控制台（國際版[國際版]，國內版[國內版]），使用郵箱或第三方賬號注冊並登錄。
注意：國內版需完成域名備案，為避免額外流程，推薦優先使用國際版。

2. 創建開發版應用

登錄後進入控制台，點擊 「創建應用」，按以下步驟操作：

  • 輸入應用名稱（自定義，如「MyBlogComments」）；
  • 選擇 「開發版」（免費額度滿足個人博客需求）；
  • 點擊 「創建」 完成應用初始化。

3. 獲取應用憑證

應用創建後，進入左側導航欄 「設置」→「應用憑證」，記錄以下關鍵信息（後續部署需用到）：

  • APP ID：應用唯一標識；
  • APP Key：應用訪問密鑰；
  • Master Key：高級操作密鑰（用於數據管理）。

重要提示：Master Key 擁有最高權限，請勿泄露給第三方。建議截圖或使用密碼管理器保存這三個密鑰。

4. 配置安全域名（可選）

為防止未授權網站調用 API，需在 「設置」→「安全中心」→「Web 安全域名」 中添加博客域名（如 https://yourblog.com）。本地調試時，localhost 會自動放行，無需額外配置。

5. 國內版特殊配置（僅國內用戶）

若使用 LeanCloud 國內版，需完成兩項額外操作：

  1. 備案綁定域名：在 LeanCloud 控制台綁定已備案的自定義域名；
  2. 記錄服務器地址：將綁定的域名（如 https://comments.yourblog.com）作為 LEAN_SERVER 環境變量值，後續部署時需配置。

國內用戶必看：未配置 LEAN_SERVER 會導致服務連接失敗。國際版用戶可跳過此步驟。

完成以上配置後，你已獲得 LeanCloud 應用的核心憑證，接下來可用於 Vercel 部署時的環境變量設置。

Vercel部署Waline服務端

通過Vercel模板部署Waline服務端是最快捷的方式，全程無需本地配置環境，只需通過網頁操作即可完成。以下是詳細步驟：

1. 部署Waline服務

首先訪問Waline官方模板頁面（可通過Waline文檔或GitHub倉庫找到），點擊頁面中的 “Deploy to Vercel” 按鈕，系統會自動跳轉至Vercel部署界面。使用GitHub賬號登錄Vercel後，輸入項目名稱（如waline-server），點擊 “Create” 創建項目，Vercel將自動基於模板初始化倉庫並開始部署。此時只需等待部署進度條完成，首次部署會生成一個臨時預覽地址，但暫不可用——因為還需要配置關鍵環境變量。

2. 配置環境變量

環境變量是Waline連接數據庫的核心配置，必須準確填寫才能確保服務正常運行。部署完成後，進入Vercel項目控制台，點擊 “Settings” > “Environment Variables”，添加以下變量：

環境變量 key 說明 示例值格式 適用場景
LEAN_ID LeanCloud 應用的 App ID iGxxxxxxxxxxxxxxxxxxxxxxA 所有用戶必須配置
LEAN_KEY LeanCloud 應用的 App Key 7fxxxxxxxxxxxxxxxxxxxxxxB 所有用戶必須配置
LEAN_MASTER_KEY LeanCloud 應用的 Master Key 9cxxxxxxxxxxxxxxxxxxxxxxC 所有用戶必須配置
LEAN_SERVER LeanCloud 服務地址 https://your-leancloud-domain.com 國內用戶額外配置

注意事項：

  • 環境變量值需從 LeanCloud 控制台的「應用設置 > 應用 Keys」中獲取，確保復制時無空格或多余字符。
  • 國內用戶若使用 LeanCloud 國內版，必須添加 LEAN_SERVER 並填寫已備案的自定義域名（需提前在 LeanCloud 綁定域名），否則會因跨域問題導致評論功能失效。

添加完成後點擊 “Save” 保存變量，此時變量不會立即生效，必須執行「重新部署」操作。

3. 重新部署項目

環境變量修改後，Vercel 不會自動更新現有部署，需手動觸發重新部署使配置生效。進入項目控制台的 “Deployments” 標簽頁，找到最新的部署記錄（通常在列表頂部），點擊右側的 “Redeploy” 按鈕，確認後等待部署完成（約1-3分鐘）。

4. 獲取服務端地址

重新部署成功後，部署記錄的 STATUS 會顯示為 “Ready”，點擊右側的 “Visit” 按鈕即可訪問服務端。此時瀏覽器地址欄的 URL（如 https://waline-server.vercel.app）即為 Waline 服務端地址，請務必復制保存——後續在 Hexo 博客配置中需要填寫該地址（對應 serverurl 參數）。

若需要自定義域名（可選），可進入 “Settings” > “Domains”，輸入你的域名（如 waline.yourblog.com），並在域名服務商處添加 CNAME 解析（指向 cname.vercel-dns.com）。配置完成後，自定義域名將作為服務端地址的替代選項，建議同時保留默認的 Vercel 域名作為備用。

關鍵提示：服務端地址是連接博客與評論系統的橋梁，若後續更換域名或重新部署，需同步更新博客配置中的 serverurl，否則評論功能會失效。

Hexo博客集成Waline

完成Waline服務端部署後，需在Hexo博客中安裝集成插件並配置主題文件，實現評論系統的前端對接。以下是詳細步驟：

一、安裝Waline集成插件

首先在Hexo博客根目錄打開終端，執行以下命令安裝Waline官方Hexo插件：

該插件會自動處理Waline客戶端資源的引入，無需手動添加腳本文件，適用於大多數主流Hexo主題。

二、主題配置文件準備

為避免直接修改主題默認配置文件（升級時可能被覆蓋），不同主題推薦采用以下方式維護配置：

  • Next主題（推薦）：
    創建獨立配置文件_config.next.yml（需Hexo 5.0+），通過命令復制默認配置：

    • npm安裝主題：cp node_modules/hexo-theme-next/_config.yml _config.next.yml
    • Git克隆主題：cp themes/next/_config.yml _config.next.yml
      後續所有配置均在_config.next.yml中進行。

  • 其他主題（Butterfly/Fluid/Yun等）：

安全與反垃圾評論

開放評論區是博客與讀者互動的重要窗口，但垃圾評論和惡意提交可能影響閱讀體驗。Waline 提供了多層次安全防護機制，通過合理配置環境變量即可有效保障評論區安全。以下是關鍵安全策略及配置指南：

一、反垃圾評論服務配置

Waline 內置多種反垃圾機制，可通過環境變量啟用專業反垃圾服務和人機驗證，從源頭攔截惡意評論。

1. Akismet 反垃圾服務
作為業界知名的反垃圾評論服務，Akismet 能自動識別垃圾評論。Waline 默認集成該服務，無需額外部署即可使用。

  • 環境變量：AKISMET_KEY
  • 作用：填寫 Akismet 服務的 API Key 以啟用功能；若無需使用，需顯式設置為 false（直接留空可能導致默認 Key 繼續生效）。
  • 默認值：70542d86693e（測試用 Key，生產環境建議替換為個人 Key）。

2. 人機驗證機制
針對自動化工具提交的惡意評論，可啟用第三方人機驗證（需服務端與客戶端同步配置）：

  • reCAPTCHA V3：需同時配置 RECAPTCHA_V3_KEY（客戶端驗證 Key）和 RECAPTCHA_V3_SECRET（服務端密鑰）。
  • Cloudflare Turnstile：輕量級驗證方案，配置 TURNSTILE_KEY 即可啟用，適合對用戶體驗要求較高的場景。

二、評論審核與內容管控

通過審核機制和頻率限制，可進一步過濾可疑評論，防止評論區被濫用。

1. 評論人工審核
開啟審核後，所有新評論需經管理員在 Waline 後台確認後才會顯示，避免不當內容直接公開。

  • 環境變量：COMMENT_AUDIT
  • 配置值：設為 true 啟用審核，false 則評論直接發布。

注意：啟用審核後需定期登錄 Waline 管理後台（通常通過 YOUR_DEPLOY_URL/ui 訪問）處理待審核評論，避免評論積壓影響互動及時性。

2. IP 評論頻率限制
限制同一 IP 地址的評論發布速度，防止短時間內大量灌水。

  • 環境變量：IPQPS
  • 作用：單位為秒，默認值 60（即 1 分鐘內同一 IP 僅允許提交 1 條評論）；設為 0 表示不限制。

三、安全域名與訪問控制

通過限制評論系統的調用來源，防止未授權網站濫用你的評論服務。

安全域名配置
指定允許提交評論的域名，僅來自這些域名的請求會被處理，有效避免跨站請求偽造（CSRF）。

  • 環境變量：SECURE_DOMAINS
  • 配置值：填寫博客域名（如 example.com），多個域名用逗號分隔（如 blog.example.com,www.example.com）。

郵件通知設置

郵件通知功能是提升博客互動體驗的重要環節，它能讓你及時收到新評論提醒，同時確保評論者在收到回復時第一時間獲知。當有新評論提交時，系統會向博主郵箱發送通知；當某條評論被回復時，則會通過評論者填寫的郵箱進行提醒。通知中的站點名稱和地址將自動讀取你在"站點管理/系統設置/站點配置"中填寫的信息。

基礎配置步驟

首先需要在系統中啟用郵件通知功能，然後填寫SMTP服務相關信息。以下是詳細配置指南：

主流郵箱SMTP參數配置

不同郵箱服務商的SMTP設置存在差異，這裏以QQ郵箱和163郵箱為例進行說明：

QQ郵箱配置

  • SMTP地址(host)：個人郵箱使用smtp.qq.com，企業郵箱使用smtp.exmail.qq.com
  • SMTP端口：465（SSL加密）或587（TLS加密）
  • SMTP用戶名：你的QQ郵箱完整地址（如12345678@qq.com）
  • SMTP密碼：需在QQ郵箱設置中生成的授權碼（非登錄密碼）
  • 發件地址：必須與SMTP用戶名一致，否則可能出現501 Mail from address must be same as authorization user錯誤

163郵箱配置（參考通用規則）

  • SMTP地址：smtp.163.com
  • SMTP端口：465或994（SSL）
  • SMTP密碼：163郵箱需開啟"SMTP服務"並設置獨立授權碼

注意事項：所有郵箱的SMTP密碼均為獨立授權碼，而非登錄密碼。獲取方式通常在郵箱設置的"賬戶"或"安全"選項中，例如QQ郵箱需進入"設置→賬戶→POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV服務"，開啟"SMTP服務"後點擊"生成授權碼"。

常見問題排查

若配置後郵件通知不生效，可按以下步驟檢查：

  1. 授權碼是否正確：確認SMTP密碼為郵箱生成的獨立授權碼，而非登錄密碼。

常見問題解決

部署失敗問題

在使用 Vercel 部署 Waline 評論系統時，可能會遇到各類失敗情況。以下是結合實際部署場景總結的常見問題及解決方案，幫助你快速定位並解決問題。

環境變量配置錯誤

這是最常見的部署失敗原因，主要表現為服務啟動後無法連接數據庫或功能異常。需重點檢查 Vercel 部署設置中的環境變量是否完整且正確：

  • 核心變量檢查：確保 LEAN_ID（應用 ID）、LEAN_KEY（應用 Key）、LEAN_MASTER_KEY（主 Key）均從 LeanCloud 應用控制台準確復制，避免多余空格或字符。
  • 重新部署生效：修改環境變量後，必須在 Vercel 項目控制台點擊 Redepoly 重新部署，直接保存變量不會觸發服務更新。

注意：環境變量名稱區分大小寫，例如 LEAN_ID 不可誤寫為 lean_id 或 Lean_Id，否則會導致服務初始化失敗。

LeanCloud 應用配置問題

若部署後出現 Not initialized 錯誤或 404 頁面，通常與 LeanCloud 應用配置相關：

  • 應用創建驗證：登錄 LeanCloud 控制台，確認目標應用已成功創建，且所在區域（如華北、華東）與 Waline 服務端匹配。
  • 權限設置檢查：進入應用「設置 > 安全中心」，確保「Web 安全域名」已添加你的博客域名（如 https://yourblog.com），或暫時關閉「Referer 驗證」進行測試。

項目關聯與部署方式問題

部分用戶會因項目未正確關聯 Git 倉庫導致部署失敗：

  • Git 倉庫關聯：通過 Vercel 導入項目時，需確保選擇正確的 Git 倉庫及分支（通常為 main 或 master），並開啟自動部署選項。
  • CLI 部署備選方案：若通過網頁端導入失敗，可在本地項目根目錄使用 Vercel CLI 執行 vercel --prod 命令強制部署，該方式會自動關聯本地倉庫並上傳代碼。

緩存與依賴問題

部署過程中可能因緩存或依賴下載異常導致失敗：

  • 清除緩存重新部署：在 Vercel 部署記錄頁面，點擊對應部署記錄右側的「更多 > Clear Cache & Redeploy」，強制清除舊緩存並重新拉取依賴。
  • 依賴源優化：若部署日誌中出現依賴下載超時，可在項目根目錄添加 .npmrc 文件，配置國內鏡像源（如 registry=https://registry.npmmirror.com）。

Vercel 部署日誌查看方法

當上述步驟無法解決問題時，需通過部署日誌定位具體錯誤：

  1. 登錄 Vercel 控制台，進入對應項目；
  2. 點擊頂部「Deployments」選項卡，選擇最近一次失敗的部署記錄；
  3. 在部署詳情頁中，查看「Build Logs」或「Runtime Logs」，重點關注標紅的錯誤信息（如 Error: LeanCloud initialization failed），根據提示進一步排查。

通過以上步驟，多數部署問題可被定位並解決。若遇到復雜錯誤，建議將完整日誌與錯誤截圖提交至 Waline 官方倉庫或相關技術社區，獲取更針對性的幫助。

評論不顯示問題

評論區空白是部署 Waline 時最常見的問題，以下是分步驟排查方案，幫你快速定位症結所在。

一、基礎配置檢查

1. 服務端地址是否正確
首先確認 Hexo 主題配置文件（如 _config.next.yml 或 _config.butterfly.yml）中的 serverURL 字段是否準確指向部署後的 Vercel 服務端地址，格式應為 https://xxxx.vercel.app（需替換為你的實際域名）。錯誤的地址會導致評論系統無法連接後端，直接造成空白。
同時檢查服務端環境變量是否完整（如 MONGODB_URI、JWT_SECRET 等），缺失關鍵變量會導致服務端無法正常啟動。

2. 重新生成博客內容
修改配置後若未重新生成，新設置不會生效。在終端執行以下命令清理緩存並重建：
hexo clean && hexo g
生成完成後重新部署（如 hexo d），並強制刷新瀏覽器頁面（快捷鍵 Ctrl+Shift+R）。

3. 驗證服務端運行狀態
直接在瀏覽器訪問你的 Waline 服務端地址（如 https://xxxx.vercel.app），若頁面顯示 “Waline server is running” 或評論管理界面，則服務端正常；若顯示 404 或錯誤頁面，需檢查 Vercel 部署日誌中的環境變量配置或構建錯誤。

2. Butterfly 主題

  • 檢查 _config.butterfly.yml 中是否正確配置 comment: waline，並填寫 serverURL。
  • 若評論區仍空白，可能是主題評論組件路徑錯誤，需修改模板文件。例如打開 <博客根目錄>\themes\butterfly\layout\includes\comments\index.ejs，確認 Waline 組件路徑是否正確，如將錯誤路徑 partials/_comments/waline 修正為主題實際使用的組件路徑（如 includes/comments/waline）。

國內訪問問題

許多用戶在部署 Waline 評論系統後會遇到國內訪問緩慢甚至無法加載的問題，這主要是因為 Vercel 默認分配的 vercel.app 域名在國內存在域名汙染問題，導致評論系統無法正常使用。不過好在 Vercel 的服務器 IP 並未被屏蔽，我們可以通過綁定自定義域名的方式徹底解決這個問題，讓國內用戶順暢訪問評論系統。

解決步驟：綁定自定義域名

1. 在 Vercel 中添加自定義域名

首先需要在 Vercel 項目中配置你的自有域名。進入 Waline 項目的 Settings → Domains 頁面，輸入你準備用於評論系統的域名（例如 comment.yourblog.com），點擊添加後等待 Vercel 驗證域名所有權。

2. 在域名服務商處設置 CNAME 解析

登錄你的域名服務商（如阿裏雲、騰訊雲等）的 DNS 管理平台，添加以下解析記錄，將自定義域名指向 Vercel 的服務器：

記錄類型 主機記錄 記錄值 說明
CNAME comment cname.vercel-dns.com 假設使用 comment 作為子域名
CNAME @ cname.vercel-dns.com 若直接使用主域名（如 yourblog.com）
CNAME www cname.vercel-dns.com 若使用 www 子域名

主機記錄可根據需求選擇，建議使用獨立子域名（如 comment）避免與博客主域名沖突。

3. 更新 Hexo 配置中的服務端地址

完成域名解析後，需要在 Hexo 的 Waline 配置中，將 serverURL 字段修改為新綁定的自定義域名（例如 https://comment.yourblog.com），確保博客能正確連接到評論系統。

注意事項

  • 域名解析生效可能需要 10 分鐘到 24 小時，可通過 ping 命令或 DNS 檢測工具確認解析狀態。
  • 若使用 LeanCloud 國內版作為數據庫，還需在 Vercel 環境變量中設置 LEAN_SERVER 為國內服務地址，確保數據交互正常。

通過以上步驟，國內用戶即可通過你的自定義域名順暢訪問 Waline 評論系統，避免因 Vercel 默認域名問題導致的訪問障礙。這種方案不僅穩定可靠，還能提升博客的專業度和用戶體驗。

Hexo文章Front-matter配置

在Hexo博客中，每篇文章的頭部都藏著一個"配置中樞"——Front-matter。這個以 --- 分隔的區域，通過 鍵: 值 的格式定義了文章的核心屬性，而 comments: true 正是開啟Waline評論系統的關鍵開關。下面我們一步步拆解如何正確配置，讓每篇文章都能順利召喚出評論區。

二、核心參數詳解

除了 comments，這些參數也直接影響評論系統的正常工作，建議按需求配置：

參數 作用說明 注意事項
title 文章標題（必填） 直接影響評論區的頁面標識
date 文章創建時間（必填，格式：YYYY-MM-DD HH:MM:SS） 需保證唯一，部分評論系統以此作為文章ID
comments 是否顯示評論區（可選，默認值：true） 設置為false時評論區完全隱藏
categories 文章分類（可選，支持多級分類） 輔助評論系統區分不同欄目內容
tags 文章標簽（可選，數組格式） 便於評論區按標簽聚合討論
description 文章摘要（可選） 會作為評論區頁面的meta描述信息

以 date 參數為例，若兩篇文章使用相同的 date 值，部分評論系統（如Gitalk、Gitment）可能會出現評論區數據錯亂，建議通過精確到分鐘的時間戳（如 2025-08-30 14:35:22）確保唯一性。

配置避坑指南

  1. 格式錯誤：冒號後必須加空格（如 title: 正確，而非 title:正確），否則Hexo會解析失敗
  2. 默認行為：若Front-matter中未顯式設置 comments，主題通常會默認開啟評論（部分主題需在 _config.yml 中全局配置）
