はじめに

多くの中国国内の開発者にとって、GitHub Pages を使って Hexo ブログをデプロイする際、アクセス速度の遅さに悩まされることがよくあります。記事の読み込みに数秒、時にはそれ以上かかり、読者体験に深刻な影響を与えます。そんな中、Netlify の登場は、まさにこの課題に対するエレガントな解決策を提供してくれます。業界で「静的サイトホスティングの最高峰」と称されるこのプラットフォームは、Hexo などの静的ブログと完璧に適合するだけでなく、一連のコア機能によってブログデプロイの効率と体験を再定義しています。

Netlify のコア優位性 早見表

  • グローバル CDN 加速：静的リソースを世界中のノードに分散し、中国国内のアクセス遅延を大幅に改善
  • 完全自動デプロイ：GitHub リポジトリと連携すれば、ローカルでコードをコミットするだけで自動ビルドがトリガーされ、手動での hexo deploy 実行という手間から解放されます
  • 無料のセキュリティ設定：SSL 証明書が自動発行され、ブログが HTTPS で安全にアクセスされることを保証します

Netlify が提供するのは単なるホスティングサービスではなく、完全な静的サイトソリューションです：カスタムドメインのバインディング、JS/CSS リソースの圧縮、環境変数の設定、ビルドログの監視まで、個人ブログのデプロイ要件を全方位でカバーします[3][4]。これから、GitHub リポジトリの連携から中国国内アクセスの最適化までの全プロセスをステップバイステップで案内し、あなたの Hexo ブログを真の「高速読み込み・自動更新」へと導きます。

デプロイ準備

環境チェック

Hexo ブログのデプロイを始める前に、ローカル環境の整合性を検証することは、後続のデプロイ失敗を防ぐための重要なステップです。この段階では、ツールのバージョン確認、ローカルプレビューテスト、コードリポジトリの完全性という3つの観点から体系的にチェックし、各項目が Netlify のビルド要件を満たしていることを確認する必要があります。

基本ツールのバージョン確認

まず、コア開発ツールが正しくインストールされ設定されていることを確認します。Hexo の実行基盤である Node.js は、互換性の問題を避けるために nvm（Node Version Manager）によるバージョン管理が推奨されます。nvm list available でインストール可能なバージョンを確認し、nvm install <version> で指定バージョン（例：Node.js 16.20.1）をインストールし、nvm use <version> で切り替えて有効化します[5]。インストール完了後、ターミナルを開いて以下のコマンドでバージョンを確認します：

  • Node.js バージョン：node -v（v16.20.1 などの具体的なバージョン番号が返ること）
  • Hexo バージョン：hexo -v（hexo-cli: 4.3.0 のような完全な情報が返ること）
  • Git バージョン：git --version（git version 2.40.0 などの有効なバージョンが返ること）[6][7]

コマンドの実行に失敗したりバージョン番号が欠落している場合は、インストール手順を再確認する必要があります：Node.js は公式サイトから安定版をダウンロードしてデフォルトインストール、Hexo は npm install -g hexo-cli でグローバルインストール、Git は公式サイトからダウンロードして環境変数の設定を完了する必要があります[6]。

  • ポート競合：Port 4000 has been used と表示された場合、hexo s -p 5000 でポートを変更します（例：5000）
  • ブラウザのプロキシ問題：Microsoft Edge では自動プロキシ設定によりアクセスが失敗する場合があり、ブラウザ設定でプロキシサーバーを無効にする必要があります[6]

プレビューページで記事一覧、テーマスタイル、ナビゲーション機能が正常に読み込まれれば、ローカル環境の設定は正しいことを示します。スタイルの乱れや空白ページが表示される場合は、npm install で依存パッケージが完全にインストールされたか、またはテーマファイルが欠落していないかを確認してください。

GitHub リポジトリの完全性チェック

Netlify のデプロイは GitHub リポジトリ内の完全なソースコードに依存しており、重要なファイルが欠落していると直接ビルド失敗の原因となります。リポジトリに以下のコアコンテンツが含まれていることを確認してください：

  • テーマファイル：themes/ ディレクトリが完全に保持されていること（例：themes/next）、テーマ設定ファイル _config.yml を含む
  • 依存関係の設定：ルートディレクトリの package.json と package-lock.json（または yarn.lock）が必須で、プロジェクトが必要とする依存バージョンが記録されています
  • Hexo 設定：_config.yml（サイト設定）と source/（記事ソースファイル）が完全にコミットされていること

Netlify デプロイ手順

リポジトリ連携とビルド設定

Hexo ブログのローカル構築とコードホスティングが完了したら、次は GitHub リポジトリを Netlify プラットフォームと連携し、ブログが正常にデプロイされてアクセス可能な静的ページを生成するための重要なビルドパラメータを設定します。

一、リポジトリ連携：GitHub と Netlify の関連付け

Netlify は Git リポジトリから直接コードをプルして自動デプロイする方式をサポートしています。GitHub アカウントでクイックログインしてリポジトリ認証を行うことを推奨します。具体的な手順は以下の通りです：

  1. ログインと新規サイト作成：Netlify 公式サイトにアクセスし、GitHub アカウントで認証ログイン後、ダッシュボードの 「New site from Git」 または 「Add a new project」 をクリックしてリポジトリ選択ページに進みます。
  2. 認証とリポジトリ選択：リポジトリソースで GitHub を選択すると、Netlify があなたの GitHub リポジトリへのアクセス権限を要求します。認証を確認した後、リストから Hexo ブログのソースコードを格納したリポジトリを選択します（コードが git push で GitHub にアップロードされていることを確認してください）。
  3. ブランチ選択：デフォルトでメインブランチ（master または main）がデプロイされます。ブログのソースコードが他のブランチにある場合は、「Branch to deploy」で手動指定してください。

注意：リポジトリにサブディレクトリ構造が含まれる場合（例：設定ファイル package.json がルートディレクトリにない場合）、Netlify で 「Base directory」 を設定して実際のパスを指定する必要があります。そうしないと、ビルドシステムが依存関係の設定を見つけられずに失敗する可能性があります。

二、ビルド設定：重要なパラメータの設定と原理

ビルド設定ページに進んだら、ビルドコマンド と 公開ディレクトリ を重点的に設定します。この2つのパラメータがデプロイの成否を直接決定します。

1. ビルドコマンド：なぜ npm install + hexo generate が必要なのか？

Hexo ブログのビルドプロセスは2つのステップに分かれます：

  • 依存関係のインストール：npm install で package.json に宣言された依存パッケージ（Hexo コアモジュール、テーマプラグインなど）をダウンロードします。このステップをスキップすると、Netlify サーバーは必要な依存関係（例：hexo-cli）が不足しているため後続コマンドを実行できず、「command failed with exit code 1」 というエラーがよく発生します。
  • 静的ファイルの生成：hexo generate（略称 hexo g）で Markdown 記事、テーマ設定などを HTML/CSS/JS の静的ファイルにコンパイルし、デフォルトで public ディレクトリに出力します。

実際の設定では、組み合わせコマンド npm install && hexo generate を直接記入するか、package.json に build スクリプトを定義して（例："build": "hexo generate"）、Netlify で npm run build と記入することもできます（スクリプトに依存関係のインストールロジックが含まれているか、Netlify が自動的に npm install を実行することを確認する必要があります）。

2. 公開ディレクトリ：静的ファイルの場所を指定

Hexo が生成した静的ファイルはデフォルトで public ディレクトリに格納されるため、Netlify の 「Publish directory」 を public に設定する必要があります。誤って他のディレクトリ（例：dist や build）に設定すると、Netlify はデプロイ可能なファイルを見つけられずに失敗します。

三、設定入力とデプロイ保存

Netlify のインターフェースでは、ビルド設定の入力はリポジトリ選択後の 「Build settings」 ステップにあります。具体的な場所は以下の通りです：

  • Build command：npm install && hexo generate または npm run build と記入（プロジェクト設定に応じて選択）。
  • Publish directory：public と固定で記入（Hexo のデフォルト出力ディレクトリ）。

パラメータに誤りがないことを確認したら、「Deploy site」 をクリックすると、Netlify が自動的にリポジトリコードのクローン、依存関係のインストール、ビルドコマンドの実行を行い、public ディレクトリの内容をグローバル CDN にデプロイします。デプロイ完了後、Netlify が生成したランダムドメイン（形式：[ランダム文字列].netlify.app）でブログにアクセスし、ページが正常に読み込まれるかを確認します。

以上の手順により、リポジトリ連携とビルド設定が完了し、Hexo ブログが Netlify 上で安定的にデプロイされることが保証されます。次節では、中国国内からのアクセス速度を最適化し、ブログの可用性をさらに向上させる方法を紹介します。

ドメイン設定と HTTPS 有効化

独自ドメインを持つことで、ブログがよりプロフェッショナルに見えるだけでなく、ユーザーの記憶にも残りやすくなります。このステップを完了すると、Netlify が自動的にブログに HTTPS 暗号化を設定し、アクセスをより安全にします。以下、ドメインバインディングとセキュリティ強化を段階的に実装します。

一、Netlify でカスタムドメインを追加

まず Netlify アカウントにログインし、Hexo ブログのサイトコンソールに入り、「Domain management」→「Production domains」で「Add domain」をクリックし、お持ちのドメイン（例：example.com）を入力して検証・確認します。追加後、このドメインがブログのメインドメインとなり、デフォルトの xxx.netlify.app サブドメインを置き換えます[9]。

注意：ドメイン追加時に重複バインドがないことを確認してください。競合のプロンプトが表示された場合は、Netlify のドメイン設定で古い DNS ゾーンレコードを削除してください[10]。

二、DNS 解決設定（Alibaba Cloud を例に）

このステップでは、ドメインプロバイダー（Alibaba Cloud、Tencent Cloud など）の管理画面で DNS レコードを変更し、ドメインを Netlify サーバーに向ける必要があります。ドメインタイプ（ネイキッドドメイン/サブドメイン）に応じて異なる設定を選択します：

ドメインタイプ 推奨レコードタイプ ホスト名 レコード値 説明
www サブドメイン CNAME www your-site.netlify.app（例：blog.netlify.app） www.example.com を Netlify が割り当てたサブドメインにポイント
ネイキッドドメイン（example.com） CNAME（サポートされている場合） @ apex-loadbalancer.netlify.com DNS プロバイダーが CNAME flattening（エイリアスレコード）をサポートしている場合、この設定を優先
ネイキッドドメイン（example.com） Aレコード（CNAME 非サポート時） @ 75.2.60.5 CNAME 非サポート時は、Aレコードを追加して Netlify ロードバランサー IP に向けます。IP のハードコーディングによる変更リスクを避けてください

設定のポイント：

  • Alibaba Cloud ユーザーは「ドメイン解決」→「レコード追加」から、上表のパラメータを入力します；
  • 以前に古いAレコード（GitHub や他のサーバー向けなど）がある場合は、先に削除してから新しいレコードを追加してください；
  • サブドメインとネイキッドドメインを同時に設定することで、example.com と www.example.com の両方でのアクセスが可能になります[10][11]。

三、DNS 有効化状態の確認

DNS レコードの更新後、即座に有効になるわけではなく、世界中の DNS サーバーが同期するのを待つ必要があります（通常10〜30分、最長48時間以内）。ターミナルコマンドで設定が有効になったかを確認できます：

  • ネイキッドドメインの確認：host example.com を実行し、返された結果に 75.2.60.5（Aレコード）または apex-loadbalancer.netlify.com（CNAME）が含まれていること；
  • www サブドメインの確認：host www.example.com を実行し、返された結果にあなたの Netlify サブドメイン（例：blog.netlify.app）が含まれていること[10]。

ヒント：DNS の伝播状況を素早く確認したい場合は、オンラインツール（DNS Checker など）を使用してドメインを入力し、世界各地での解決状態を確認できます。

四、HTTPS 自動有効化とセキュリティ価値

DNS が正しく Netlify に向けられると、システムは自動的に以下の操作を完了します：

  1. 証明書生成：Netlify が Let’s Encrypt を通じて無料の SSL 証明書を自動発行し、手動アップロードは不要です；
  2. HTTPS 有効化：デフォルトで HTTPS が有効になり、強制リダイレクトされます（HTTP リクエストは自動的に HTTPS に転送されます）；
  3. 証明書更新：証明書の有効期限は90日で、Netlify が事前に自動更新するため、手動での介入は不要です[3][12]。

なぜ HTTPS を有効にしなければならないのか？

  • セキュリティ面：ユーザーデータの転送を暗号化し、コンテンツの改ざんを防止します；
  • 体験面：最新のブラウザ（Chrome、Firefox など）は HTTP サイトに「保護されていません」と表示し、アクセス意欲に影響します；
  • SEO 面：Google などの検索エンジンは HTTPS サイトを優先的に収録し、ランキングの重みを高めます[13]。

HTTPS が有効化されない場合は、まず DNS レコードが正しいかを確認し（誤った DNS の向き先は証明書生成の失敗原因となります）、その後 Netlify の「HTTPS」設定で「Renew certificate」をクリックして手動で証明書更新をトリガーしてください[14]。

以上の手順を完了すると、あなたの Hexo ブログは独自ドメインと HTTPS 暗号化を手に入れ、アクセス速度とセキュリティの両方が大幅に向上します。

「build command failed」エラーの解決策

依存関係のインストールとバージョン互換性の問題

Hexo ブログを Netlify にデプロイする過程で、ビルド失敗はしばしば依存関係のインストール不完全やバージョン互換性の問題と関連しています。これらの問題の根本原因は Netlify ビルド環境の特性と密接に関係しており、デプロイフローを円滑にするためには的を絞った解決が必要です。

依存関係のインストール：「command not found」から完全なデプロイへ

Netlify のビルド環境はデフォルトで本番モード（NODE_ENV=production）で実行され、このモードでは package.json の dependencies フィールドに宣言された依存関係のみがインストールされ、devDependencies のツール（例：hexo-cli）は自動的にインストールされません。これは、ビルドログに「command not found」（例：「hexo: command not found」）やモジュール欠落エラーが直接表示される原因となります。

この問題を解決する核心は、ビルドツールと依存関係が環境内で利用可能であることを保証することです。よく使われる2つの方法があります：

  • 方法1：ビルドコマンドの調整

よくある落とし穴の注意：デプロイ時に「ERROR Deployer not found: git」が表示された場合は、npm install hexo-deployer-git --save で欠落しているデプロイプラグインを手動インストールする必要があります。この種のツールは通常、Hexo コアと一緒に自動インストールされません。

おわりに

Netlify で Hexo ブログをデプロイすることで、面倒な手動デプロイフローから解放され、ローカル修正、GitHub コミットから自動デプロイまでの全プロセス自動化を実現し、ブログ公開の効率が大幅に向上します[1][8]。同時に、Netlify が提供する無料の HTTPS 証明書と柔軟な DNS 設定は、ブログのセキュリティを強化するだけでなく、サイトのグローバルな可用性を効果的に高め、中国国内からのアクセス体験をよりスムーズにします。

もちろん、デプロイプロセスではいくつかの重要な詳細に注意する必要があります。コア注意事項：プロジェクトの依存関係管理を明確にし、バージョン競合によるビルド失敗を避けること；DNS 設定時にはドメイン解決レコードを慎重に確認し、解決先が正しいことを保証すること；ビルドコマンドは事前にローカルで検証し、コマンドエラーによるデプロイ中断を避けること。これらの詳細のコントロールが、ブログをスムーズに公開するための重要な保証となります。

もしブログデプロイの複雑さにまだ悩まされているなら、この記事の手順に従って実際に試してみてください。デプロイ完了後は、定期的に Netlify のビルドログとドメイン解決状態を確認し、潜在的な問題を早期に発見・解決することで、Hexo ブログを長期的に安定稼働させ、読者により信頼性の高いアクセス体験を提供しましょう。技術の価値はプロセスの簡素化と効率の向上にあります。Netlify と Hexo の組み合わせは、まさにこの理念の最良の実践です。
