概要

最近、多くの方からコメントシステムについてご質問をいただきました。静的ブログユーザーにとって、コメントシステムの構築は「利便性と安全性の両立が難しい」というジレンマに陥りがちです。バックエンド不要のソリューションは軽量である一方でデータ漏洩のリスクがあり、従来のバックエンド型システムは導入ハードルが高すぎます。そこでWalineは、Valineをベースに開発された新世代のコメントシステムとして、「バックエンドアーキテクチャ＋軽量デプロイ」という革新的なモデルにより、安全性と使いやすさを完璧にバランスさせました。Hexoなどの静的ブログにとって理想的な選択肢であり、当サイトもこのコメントシステムを採用しています。そのため、多くの文献を参考にこの記事を執筆しました。

Waline：コメントシステムを安全かつ強力に

WalineはValineのシンプルな遺伝子を受け継ぎつつ、セキュリティコアと機能の深さを重点的に強化しています。多重暗号化技術を用いてユーザーデータを保護し、ValineがフロントエンドでLeanCloudキーを露出していたことによるセキュリティ上の問題を根本から解決しました。同時に、匿名ログインのコンテンツ検証、スパム防止メカニズム、機密情報フィルタリングにより、スパムコメント攻撃を効果的に防御します。機能面では、プロフェッショナルなコミュニティに匹敵するインタラクティブ体験を提供します。テキスト、絵文字、画像など多様なコメント形式に対応し、Markdown構文、数式、HTML埋め込みにも互換性があります。コメント審査、返信通知、通報処理などの管理ツールを内蔵し、複数のテーマスタイルとカスタム設定を組み合わせることで、個人ブログから技術サイトまで多様なニーズに対応します。

Walineの主な利点
✅ セキュリティ強化：Valineアーキテクチャを再構築、多重暗号化保護＋スパム防止メカニズム
✅ 機能充実：Markdown/絵文字/画像コメント対応、コメント管理とマルチプラットフォームログイン内蔵
✅ クロスプラットフォーム対応：Hexo、VuePressなどの静的ブログシステムとシームレスに連携

なぜVercelでのデプロイを選ぶのか？

バックエンドを持つコメントシステムとして、Walineには独立したサーバーサイドのサポートが必要です。Vercelはその「運用ゼロ」という特性から、最適なデプロイソリューションとなっています。この人気のフロントエンドデプロイプラットフォームはワンストップソリューションを提供します。GitHubリポジトリとの連携でデプロイが完了し、コマンドライン操作は一切不要です。グローバルCDNノードによりコメントの読み込みはミリ秒単位で応答します。無料プランには自動SSL証明書、Serverless関数サポート、無制限トラフィックが含まれ、個人ブログの利用シーンを完全にカバーします。他のデプロイ方法と比較して、Vercelは本来数時間かかるサーバー設定プロセスを「クリック認証→自動デプロイ」の数分間に圧縮し、技術初心者でもプロフェッショナルなコメントシステムを簡単に導入できます。

本記事では**「VercelデプロイWaline＋Hexo統合」**の完全なフローに焦点を当て、サーバーサイドデプロイ、データベース設定からフロントエンド統合まで、再利用可能な操作ガイドと注意点を提供します。コメントシステムに初めて触れるブログ初心者でも、既存のコメント機能をアップグレードしたい上級ユーザーでも、このチュートリアルを通じて15分以内に安全で効率的かつ美しいインタラクティブシステムを構築し、静的ブログを真に「生きた」ものにすることができます。

事前準備

Walineコメントシステムのデプロイを開始する前に、以下の準備が完了していることを確認してください。これにより、後続のデプロイフローをスムーズに進めることができます。アカウント登録、ツール環境設定、ブログ環境チェックの3つの観点から整理し、重要な注意点を示します。

一、コアアカウントの準備

Walineのデプロイには2つの重要なプラットフォームが必要です：Vercel（サーバーサイドデプロイ）とLeanCloud（データストレージ）です。事前に登録と基本設定を完了することをお勧めします。

1. Vercelアカウント

  • 役割：Walineサーバーサイドのホスティングプラットフォームとして、無料デプロイとグローバルCDN加速機能を提供します。
  • 登録方法：公式サイトにアクセスし、GitHubアカウントでのクイックログインを推奨します（追加登録不要で、直接コードリポジトリと連携できます）。
  • 注意点：ログイン後の追加設定は不要で、後続のデプロイ時にWalineコードリポジトリを直接関連付けるだけです。

2. LeanCloudアカウント

  • 役割：データベースサービスを提供し、コメント内容やユーザー情報などのコアデータを保存します。
  • 登録と設定：
    1. leancloudにアクセスし、アカウントを登録します（国内ユーザーは華東/華北ノードを推奨、海外ユーザーは国際版を選択可能）。
    2. アプリ作成：コンソールに入り「アプリ作成」をクリックし、「開発版」を選択します（無料枠で個人ブログのニーズを満たせます）。
    3. キーの取得：アプリ設定の「アプリKeys」で、App ID、App Key、Master Keyを記録します（後続のデプロイでこの3つのパラメータを入力する必要があります）。
  • 特別要件：国内ノードのアプリはICP登録済みドメインのバインドが追加で必要です（パス：設定 → セキュリティセンター → Webセキュリティドメイン）。これがないとコメントデータの正常な読み書きができません。

二、ローカルツール環境の設定

以下のツールがローカルにインストールされていることを確認してください。デプロイコマンドの実行とHexoブログの管理に使用します。

1. 基本開発環境

  • Node.js と npm/yarn

    • 役割：Hexoブログの実行とWaline関連の依存関係のインストール。
    • 確認方法：ターミナルで node -v と npm -v（または yarn -v）を実行し、バージョン番号が出力されればインストール済みです（Node.js ≥ 14.0.0、npm ≥ 6.0.0 を推奨）。

  • Git

    • 役割：バージョン管理ツール。Walineのソースコード取得とHexoブログコードの管理に使用。
    • 確認方法：ターミナルで git --version を実行し、バージョン番号が出力されれば正常です。

2. Vercel CLI（オプションだが推奨）

  • 役割：ローカルでVercelデプロイコマンドを実行でき、毎回Webコンソールにログインする必要がなくなります。
  • インストール方法：ターミナルで npm i -g vercel を実行（グローバルインストール）。インストール後、vercel -v でバージョンを確認します。

三、Hexoブログ環境のチェック

Walineをデプロイする前に、Hexoブログが正常に動作し、テーマがコメントシステム設定をサポートしていることを確認する必要があります。

  • 基本環境：hexo init でブログプロジェクトを作成済みで、hexo s を実行してローカル http://localhost:4000 でプレビューできること。
  • テーマ互換性：Waline対応テーマ（Next（≥8.18.2）、Yun、Seaなど）の使用を推奨。テーマ設定ファイル（_config.next.yml など）にコメントシステム関連の設定項目が存在することを確認してください。
  • 設定ファイルの規範：テーマ設定ファイルの上書きによる設定を推奨します（テーマのデフォルト設定を直接変更しない）。例えば、ブログルートディレクトリに _config.next.yml を作成してテーマ設定を個別管理します。

四、オプション準備：カスタムドメイン（必要に応じて設定）

Walineサービスにアクセスするためにパーソナライズドメイン（comment.yourblog.com など）を使用する場合は、事前に以下を準備してください。

  • 登録済みドメイン（国内ユーザー）、ドメイン解決プラットフォームでVercelを指すCNAMEレコードを追加。
  • 用途：VercelにデプロイされたサーバーサイドまたはLeanCloud国内版アプリのバインド（ドメイン制限問題の解決）。

重要なヒント：すべてのアカウント登録が完了したら、関連キー（LeanCloudのMaster Keyなど）を適切に保管してください。後続のデプロイ手順で頻繁に使用します。LeanCloud国内版を使用する場合は、ドメイン登録とバインドを事前に完了し、クロスドメイン問題によるコメント機能の失效を防いでください。

以上の準備が完了したら、WalineサーバーサイドのデプロイとHexo統合に進むことができます。

詳細手順

LeanCloud設定

Walineコメントシステムのデータ保存はLeanCloudプラットフォームに依存しています。まずアカウント登録とアプリ設定を完了する必要があります。以下は詳細な手順です。

1. 登録とログイン

LeanCloudコンソール（国際版：国際版、国内版：国内版）にアクセスし、メールアドレスまたはサードパーティアカウントで登録・ログインします。
注意：国内版はドメイン登録が必要なため、追加の手続きを避けるために国際版の使用を優先推奨します。

2. 開発版アプリの作成

ログイン後、コンソールに入り 「アプリ作成」 をクリックし、以下の手順で操作します。

  • アプリ名を入力（任意、「MyBlogComments」など）。
  • 「開発版」 を選択（無料枠で個人ブログのニーズを満たせます）。
  • 「作成」 をクリックしてアプリの初期化を完了します。

3. アプリ認証情報の取得

アプリ作成後、左側ナビゲーションバーの 「設定」→「アプリ認証情報」 に入り、以下の重要情報を記録します（後続のデプロイで使用）。

  • APP ID：アプリの一意識別子。
  • APP Key：アプリアクセスキー。
  • Master Key：高度な操作用キー（データ管理に使用）。

重要な注意：Master Keyは最高権限を持つため、第三者に漏洩しないでください。スクリーンショットを撮るか、パスワードマネージャーを使用してこれら3つのキーを保存することをお勧めします。

4. セキュリティドメインの設定（オプション）

未許可のWebサイトからのAPI呼び出しを防ぐために、「設定」→「セキュリティセンター」→「Webセキュリティドメイン」 でブログドメイン（https://yourblog.com など）を追加します。ローカルデバッグ時は、localhost が自動的に許可されるため、追加設定は不要です。

5. 国内版の特別設定（国内ユーザーのみ）

LeanCloud国内版を使用する場合、以下の2つの追加操作が必要です。

  1. 登録済みドメインのバインド：LeanCloudコンソールで登録済みのカスタムドメインをバインド。
  2. サーバーアドレスの記録：バインドしたドメイン（https://comments.yourblog.com など）を LEAN_SERVER 環境変数の値として記録し、後続のデプロイ時に設定します。

国内ユーザー必見：LEAN_SERVER を設定しないとサービス接続に失敗します。国際版ユーザーはこの手順をスキップできます。

以上の設定が完了すると、LeanCloudアプリのコア認証情報を取得でき、次はVercelデプロイ時の環境変数設定に使用できます。

VercelでWalineサーバーサイドをデプロイ

Vercelテンプレートを使用してWalineサーバーサイドをデプロイするのが最も迅速な方法で、ローカル環境の設定は一切不要で、Web操作のみで完了します。以下は詳細な手順です。

1. Walineサービスのデプロイ

まずWaline公式テンプレートページ（WalineドキュメントまたはGitHubリポジトリから見つけられます）にアクセスし、ページ内の “Deploy to Vercel” ボタンをクリックすると、システムが自動的にVercelデプロイ画面に遷移します。GitHubアカウントでVercelにログイン後、プロジェクト名（waline-server など）を入力し、“Create” をクリックしてプロジェクトを作成します。Vercelが自動的にテンプレートを基にリポジトリを初期化し、デプロイを開始します。デプロイのプログレスバーが完了するのを待つだけで、初回デプロイでは一時的なプレビューアドレスが生成されますが、まだ使用できません。重要な環境変数を設定する必要があるためです。

2. 環境変数の設定

環境変数はWalineがデータベースに接続するための中核設定であり、正確に入力しないとサービスが正常に動作しません。デプロイ完了後、Vercelプロジェクトコンソールに入り、“Settings” > “Environment Variables” をクリックして、以下の変数を追加します。

環境変数 key 説明 値の形式例 適用シーン
LEAN_ID LeanCloudアプリのApp ID iGxxxxxxxxxxxxxxxxxxxxxxA 全ユーザー必須
LEAN_KEY LeanCloudアプリのApp Key 7fxxxxxxxxxxxxxxxxxxxxxxB 全ユーザー必須
LEAN_MASTER_KEY LeanCloudアプリのMaster Key 9cxxxxxxxxxxxxxxxxxxxxxxC 全ユーザー必須
LEAN_SERVER LeanCloudサービスアドレス https://your-leancloud-domain.com 国内ユーザー追加設定

注意点：

  • 環境変数の値はLeanCloudコンソールの「アプリ設定 > アプリKeys」から取得し、コピー時にスペースや余分な文字が入らないようにしてください。
  • 国内ユーザーがLeanCloud国内版を使用する場合、必ず LEAN_SERVER を追加し、登録済みのカスタムドメインを入力してください（事前にLeanCloudでドメインをバインドする必要があります）。これがないとクロスドメイン問題によりコメント機能が失效します。

追加完了後、“Save” をクリックして変数を保存します。この時点では変数はすぐに有効になりません。必ず「再デプロイ」操作を実行する必要があります。

3. プロジェクトの再デプロイ

環境変数を変更した後、Vercelは既存のデプロイを自動更新しないため、手動で再デプロイをトリガーして設定を有効にする必要があります。プロジェクトコンソールの “Deployments” タブに入り、最新のデプロイ記録（通常リストの最上部にあります）を見つけ、右側の “Redeploy” ボタンをクリックし、確認後デプロイ完了を待ちます（約1〜3分）。

4. サーバーサイドアドレスの取得

再デプロイが成功すると、デプロイ記録のSTATUSが “Ready” と表示されます。右側の “Visit” ボタンをクリックしてサーバーサイドにアクセスします。このときブラウザのアドレスバーのURL（https://waline-server.vercel.app など）が Walineサーバーサイドアドレス です。必ずコピーして保存してください。後続のHexoブログ設定でこのアドレスを入力する必要があります（serverurl パラメータに対応）。

カスタムドメインが必要な場合（オプション）、“Settings” > “Domains” に入り、ドメイン（waline.yourblog.com など）を入力し、ドメインサービスプロバイダーでCNAME解決を追加します（cname.vercel-dns.com を指す）。設定完了後、カスタムドメインがサーバーサイドアドレスの代替オプションとして使用できます。デフォルトのVercelドメインもバックアップとして保持することをお勧めします。

重要なヒント：サーバーサイドアドレスはブログとコメントシステムをつなぐ架け橋です。後日ドメインを変更したり再デプロイしたりした場合は、ブログ設定の serverurl を同期して更新する必要があります。そうしないとコメント機能が失效します。

セキュリティとスパム対策

オープンなコメントエリアはブログと読者のインタラクションの重要な窓口ですが、スパムコメントや悪意のある投稿は読書体験に影響を与える可能性があります。Walineは多層的なセキュリティ保護メカニズムを提供し、環境変数を適切に設定することでコメントエリアの安全を効果的に確保できます。以下は主要なセキュリティ戦略と設定ガイドです。

一、スパム対策サービスの設定

Walineには複数のスパム対策メカニズムが内蔵されており、環境変数でプロフェッショナルなスパム対策サービスとボット検証を有効にして、悪意のあるコメントを根本からブロックします。

1. Akismetスパム対策サービス
業界で有名なスパム対策サービスとして、Akismetは自動的にスパムコメントを識別します。Walineはデフォルトでこのサービスを統合しており、追加デプロイなしで使用できます。

  • 環境変数：AKISMET_KEY
  • 役割：AkismetサービスのAPI Keyを入力して機能を有効にします。使用しない場合は明示的に false に設定する必要があります（空のままにするとデフォルトKeyが引き続き有効になる可能性があります）。
  • デフォルト値：70542d86693e（テスト用Key、本番環境では個人Keyへの置き換えを推奨）。

2. ボット検証メカニズム
自動化ツールによる悪意のあるコメント投稿に対抗するため、サードパーティのボット検証を有効にできます（サーバーサイドとクライアントサイドの同期設定が必要）。

  • reCAPTCHA V3：RECAPTCHA_V3_KEY（クライアント検証Key）と RECAPTCHA_V3_SECRET（サーバーサイドシークレット）の両方を設定する必要があります。
  • Cloudflare Turnstile：軽量な検証ソリューションで、TURNSTILE_KEY を設定するだけで有効になります。ユーザー体験を重視するシーンに適しています。

二、コメント審査とコンテンツ管理

審査メカニズムと頻度制限により、不審なコメントをさらにフィルタリングし、コメントエリアの悪用を防ぎます。

1. コメント手動審査
審査を有効にすると、すべての新規コメントは管理者がWaline管理画面で確認した後に表示され、不適切なコンテンツの直接公開を防ぎます。

  • 環境変数：COMMENT_AUDIT
  • 設定値：true で審査を有効化、false でコメントを直接公開。

注意：審査を有効にした後は、定期的にWaline管理画面（通常 YOUR_DEPLOY_URL/ui からアクセス）にログインして保留中のコメントを処理する必要があります。コメントの滞留がインタラクションの即時性に影響しないようにしてください。

2. IPコメント頻度制限
同一IPアドレスからのコメント投稿速度を制限し、短時間での大量投稿を防ぎます。

  • 環境変数：IPQPS
  • 役割：単位は秒で、デフォルト値は 60（1分間に同一IPから1件のコメントのみ許可）。0 に設定すると制限なしになります。

三、セキュリティドメインとアクセス制御

コメントシステムの呼び出し元を制限することで、未許可のWebサイトがコメントサービスを悪用するのを防ぎます。

セキュリティドメインの設定
コメント投稿を許可するドメインを指定します。これらのドメインからのリクエストのみが処理され、クロスサイトリクエストフォージェリ（CSRF）を効果的に防止します。

  • 環境変数：SECURE_DOMAINS
  • 設定値：ブログドメイン（example.com など）を入力します。複数ドメインはカンマで区切ります（blog.example.com,www.example.com など）。

メール通知設定

メール通知機能はブログのインタラクション体験を向上させる重要な要素です。新しいコメントがあったときにタイムリーに通知を受け取ることができ、コメント投稿者は返信があったときにすぐに知ることができます。新しいコメントが投稿されると、システムはブログ管理者のメールアドレスに通知を送信します。コメントに返信があった場合は、コメント投稿者が入力したメールアドレスを通じて通知されます。通知内のサイト名とアドレスは、「サイト管理/システム設定/サイト設定」で入力した情報が自動的に読み取られます。

基本設定手順

まずシステムでメール通知機能を有効にし、次にSMTPサービス関連情報を入力する必要があります。以下は詳細な設定ガイドです。

主要メールサービスのSMTPパラメータ設定

メールサービスプロバイダーによってSMTP設定が異なります。ここではQQメールと163メールを例に説明します。

QQメール設定

  • SMTPアドレス(host)：個人メールは smtp.qq.com、企業メールは smtp.exmail.qq.com を使用
  • SMTPポート：465（SSL暗号化）または 587（TLS暗号化）
  • SMTPユーザー名：QQメールの完全なアドレス（12345678@qq.com など）
  • SMTPパスワード：QQメール設定で生成された認証コード（ログインパスワードではありません）
  • 送信元アドレス：SMTPユーザー名と一致している必要があります。一致しない場合、501 Mail from address must be same as authorization user エラーが発生する可能性があります

163メール設定（一般的なルールを参照）

  • SMTPアドレス：smtp.163.com
  • SMTPポート：465 または 994（SSL）
  • SMTPパスワード：163メールは「SMTPサービス」を有効にし、独立した認証コードを設定する必要があります

注意事項：すべてのメールのSMTPパスワードは独立した認証コードであり、ログインパスワードではありません。取得方法は通常、メール設定の「アカウント」または「セキュリティ」オプションにあります。例えば、QQメールは「設定→アカウント→POP3/IMAP/SMTP/Exchange/CardDAV/CalDAVサービス」に入り、「SMTPサービス」を有効にした後「認証コード生成」をクリックします。

環境変数設定（Dockerデプロイシーン）

WalineをDocker Composeでデプロイしている場合、docker-compose.yml に以下の環境変数を追加する必要があります。

コア環境変数の説明

メール通知を設定する際は、必須変数と任意変数を区別し、重要なパラメータが正しく設定されていることを確認する必要があります。

必須変数

  • SMTP_SERVICE/SMTP_HOST/SMTP_PORT：メールサーバー情報（いずれかを選択。SMTP_SERVICE は主要サービスプロバイダーのサーバー情報を自動入力）
  • SMTP_USER：送信者メールアドレス
  • SMTP_PASS：メール認証コード
  • SITE_NAME/SITE_URL：ブログ名とアドレス（通知内容のサイト識別に使用）
  • AUTHOR_EMAIL：ブログ管理者メール（新規コメント通知を受け取る。管理者自身のコメントは通知をトリガーしません）

任意変数（通知体験のカスタマイズ）

  • SENDER_NAME：カスタム送信者名（「ブログアシスタント」など）
  • MAIL_SUBJECT/MAIL_TEMPLATE：コメント返信メールの件名と内容テンプレート
  • MAIL_SUBJECT_ADMIN/MAIL_TEMPLATE_ADMIN：管理者が新規コメントを受け取る通知の件名と内容テンプレート

カスタムメールテンプレート

MAIL_TEMPLATE 変数を変更することで、ブログのスタイルに合った通知メールをデザインできます。テンプレートはHTML形式をサポートしていますが、内部のダブルクォーテーションはバックスラッシュでエスケープする必要があります（\" のように）。以下はテンプレート例で、コメントのコンテキスト表示とブランド要素を含みます。

テンプレート内の {{site.name}}、{{parent.nick}} などは動的変数で、自動的に実際の内容に置き換えられます。

  • {{site.name}}/{{site.url}}：ブログ名とアドレス
  • {{parent.nick}}/{{parent.comment}}：返信を受けた人のニックネームとコメント内容
  • {{self.nick}}/{{self.comment}}：返信者のニックネームと返信内容
  • {{url}}：コメントがあるページのリンク

よくある問題のトラブルシューティング

設定後にメール通知が機能しない場合は、以下の手順で確認してください。

  1. 認証コードが正しいか：SMTPパスワードがメールで生成された独立した認証コードであり、ログインパスワードでないことを確認。
  2. ポートと暗号化方式の一致：ポート465は SMTP_SECURE: 'true'、ポート587は通常 SMTP_SECURE: 'false' に対応。
  3. 送信元アドレスの一致：SMTP_USER が実際の送信元アドレスと完全に一致していることを確認。
  4. サービス再起動：設定変更後、Walineサービスを再起動して設定を反映させます。

以上の設定により、ブログのコメントシステムは完全なメール通知機能を備え、ブログ管理者の管理効率を向上させるとともに、訪問者によりタイムリーなインタラクションフィードバックを感じてもらうことができます。

よくある問題の解決

デプロイ失敗の問題

VercelでWalineコメントシステムをデプロイする際、さまざまな失敗状況に遭遇する可能性があります。以下は実際のデプロイシーンに基づいてまとめたよくある問題と解決策で、問題の迅速な特定と解決に役立ちます。

環境変数の設定ミス

これは最も一般的なデプロイ失敗の原因で、主にサービス起動後にデータベースに接続できない、または機能異常として現れます。Vercelデプロイ設定の環境変数が完全かつ正確であるかを重点的に確認する必要があります。

  • コア変数のチェック：LEAN_ID（アプリID）、LEAN_KEY（アプリKey）、LEAN_MASTER_KEY（マスターKey）がすべてLeanCloudアプリコンソールから正確にコピーされていることを確認し、余分なスペースや文字を避けます。
  • 再デプロイで反映：環境変数を変更した後は、必ずVercelプロジェクトコンソールで Redepoly をクリックして再デプロイする必要があります。変数を保存するだけではサービス更新はトリガーされません。

注意：環境変数名は大文字と小文字を区別します。例えば LEAN_ID を lean_id や Lean_Id と誤って記述すると、サービス初期化に失敗します。

LeanCloudアプリ設定の問題

デプロイ後に Not initialized エラーや404ページが表示される場合は、通常LeanCloudアプリ設定に関連しています。

  • アプリ作成の確認：LeanCloudコンソールにログインし、対象アプリが正常に作成され、所在リージョン（華北、華東など）がWalineサーバーサイドと一致していることを確認。
  • 権限設定のチェック：アプリの「設定 > セキュリティセンター」に入り、「Webセキュリティドメイン」にブログドメイン（https://yourblog.com など）が追加されていることを確認するか、一時的に「Referer検証」を無効にしてテストします。

プロジェクト関連付けとデプロイ方式の問題

一部のユーザーはプロジェクトがGitリポジトリに正しく関連付けられていないためにデプロイに失敗します。

  • Gitリポジトリ関連付け：Vercelでプロジェクトをインポートする際、正しいGitリポジトリとブランチ（通常 main または master）を選択し、自動デプロイオプションを有効にする必要があります。
  • CLIデプロイ代替案：Web画面からのインポートに失敗した場合、ローカルプロジェクトのルートディレクトリでVercel CLIを使用して vercel --prod コマンドを実行すると強制デプロイできます。この方法では自動的にローカルリポジトリを関連付け、コードをアップロードします。

キャッシュと依存関係の問題

デプロイプロセス中にキャッシュや依存関係のダウンロード異常により失敗する場合があります。

  • キャッシュクリアと再デプロイ：Vercelのデプロイ記録ページで、該当デプロイ記録の右側にある「詳細 > Clear Cache & Redeploy」をクリックし、古いキャッシュを強制的にクリアして依存関係を再取得します。
  • 依存関係ソースの最適化：デプロイログに依存関係ダウンロードのタイムアウトが表示される場合、プロジェクトのルートディレクトリに .npmrc ファイルを追加し、国内ミラーソース（registry=https://registry.npmmirror.com など）を設定します。

Vercelデプロイログの確認方法

上記の手順で問題が解決できない場合は、デプロイログで具体的なエラーを特定する必要があります。

  1. Vercelコンソールにログインし、該当プロジェクトに入る。
  2. 上部の「Deployments」タブをクリックし、最新の失敗したデプロイ記録を選択。
  3. デプロイ詳細ページで「Build Logs」または「Runtime Logs」を表示し、赤くハイライトされたエラー情報（Error: LeanCloud initialization failed など）に注目し、プロンプトに従ってさらに調査します。

以上の手順により、ほとんどのデプロイ問題は特定して解決できます。複雑なエラーに遭遇した場合は、完全なログとエラースクリーンショットをWaline公式リポジトリや関連技術コミュニティに提出し、より的確なサポートを受けることをお勧めします。

コメントが表示されない問題

コメントエリアが空白になるのは、Walineをデプロイする際に最もよくある問題です。以下は段階的なトラブルシューティング手順で、原因を迅速に特定するのに役立ちます。

一、基本設定のチェック

1. サーバーサイドアドレスが正しいか
まずHexoテーマ設定ファイル（_config.next.yml や _config.butterfly.yml など）の serverURL フィールドが、デプロイ後のVercelサーバーサイドアドレスを正確に指していることを確認します。形式は https://xxxx.vercel.app である必要があります（実際のドメインに置き換えてください）。間違ったアドレスはコメントシステムがバックエンドに接続できず、直接空白を引き起こします。
同時に、サーバーサイドの環境変数が完全であるか（MONGODB_URI、JWT_SECRET など）を確認します。重要な変数が欠けているとサーバーサイドが正常に起動できません。

2. ブログコンテンツの再生成
設定を変更した後に再生成しないと、新しい設定は反映されません。ターミナルで以下のコマンドを実行してキャッシュをクリアし、再構築します。
hexo clean && hexo g
生成完了後、再デプロイ（hexo d など）し、ブラウザページを強制リフレッシュします（ショートカット Ctrl+Shift+R）。

3. サーバーサイドの動作状態確認
ブラウザでWalineサーバーサイドアドレス（https://xxxx.vercel.app など）に直接アクセスし、ページに “Waline server is running” またはコメント管理画面が表示されれば、サーバーサイドは正常です。404やエラーページが表示される場合は、Vercelデプロイログの環境変数設定やビルドエラーを確認する必要があります。

二、テーマ互換性の処理

HexoテーマによってWalineのサポート度が異なるため、テーマごとに対応が必要です。

1. Nextテーマ

  • 推奨案：テーマバージョンが 8.14.0 以上であることを確認します。新バージョンではWalineサポートが内蔵されており、テーマ設定で直接有効化できます。
  • 旧バージョン処理：アップグレードできない場合は、手動で記事テンプレートにコメントコンテナを追加する必要があります。Webサイトを参照してください。

2. Butterflyテーマ

  • _config.butterfly.yml で comment: waline が正しく設定され、serverURL が入力されていることを確認します。
  • コメントエリアがまだ空白の場合は、テーマのコメントコンポーネントパスが間違っている可能性があります。テンプレートファイルを修正する必要があります。例えば <ブログルートディレクトリ>\themes\butterfly\layout\includes\comments\index.ejs を開き、Walineコンポーネントパスが正しいか確認します。誤ったパス partials/_comments/waline をテーマが実際に使用しているコンポーネントパス（includes/comments/waline など）に修正します。

国内アクセスの問題

多くのユーザーがWalineコメントシステムをデプロイした後、国内アクセスが遅い、または読み込めない問題に遭遇します。これは主に、Vercelがデフォルトで割り当てる vercel.app ドメインが国内でドメイン汚染の問題を抱えているためで、コメントシステムが正常に使用できなくなります。しかし幸いなことに、VercelのサーバーIPはブロックされていません。カスタムドメインのバインドによってこの問題を完全に解決し、国内ユーザーがコメントシステムにスムーズにアクセスできるようにすることが可能です。

解決手順：カスタムドメインのバインド

1. Vercelでカスタムドメインを追加

まずVercelプロジェクトで独自ドメインを設定する必要があります。Walineプロジェクトの Settings → Domains ページに入り、コメントシステム用に準備したドメイン（comment.yourblog.com など）を入力し、追加後Vercelがドメイン所有権を検証するのを待ちます。

2. ドメインサービスプロバイダーでCNAME解決を設定

ドメインサービスプロバイダー（Alibaba Cloud、Tencent Cloudなど）のDNS管理プラットフォームにログインし、以下の解決レコードを追加して、カスタムドメインをVercelのサーバーに向けます。

レコードタイプ ホストレコード レコード値 説明
CNAME comment cname.vercel-dns.com サブドメイン comment を使用する場合
CNAME @ cname.vercel-dns.com メインドメイン（yourblog.com）を直接使用する場合
CNAME www cname.vercel-dns.com www サブドメインを使用する場合

ホストレコードは必要に応じて選択可能です。ブログのメインドメインとの競合を避けるために、独立したサブドメイン（comment など）の使用を推奨します。

3. Hexo設定のサーバーサイドアドレスを更新

ドメイン解決が完了したら、HexoのWaline設定で serverURL フィールドを新しくバインドしたカスタムドメイン（https://comment.yourblog.com など）に変更し、ブログがコメントシステムに正しく接続できるようにします。

注意事項

  • ドメイン解決の反映には10分から24時間かかる場合があります。ping コマンドやDNS検出ツールで解決状態を確認できます。
  • LeanCloud国内版をデータベースとして使用している場合は、Vercel環境変数で LEAN_SERVER を国内サービスアドレスに設定し、データのやり取りが正常に行われるようにする必要があります。

以上の手順により、国内ユーザーはカスタムドメインを通じてWalineコメントシステムにスムーズにアクセスでき、Vercelのデフォルトドメイン問題によるアクセス障害を回避できます。このソリューションは安定性と信頼性が高いだけでなく、ブログのプロフェッショナル性とユーザー体験も向上させます。
